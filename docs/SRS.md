### 0.2 用語

- **草稿（Draft）**：使用者可編輯的文章內容。**確認（Confirm）**：使用者檢視完整預覽後明確同意，系統保存不可變快照與雜湊。
- **遞送（Delivery）**：把已確認的內容交到使用者的 PTT 終端機前的過程，分兩種模式：**模式 A 剪貼簿**、**模式 B Windows UI 自動輸入**。遞送**不包含**存檔、發文或任何送出動作。
- **發文（Post）**：在 PTT 內完成最後存檔並發布。**永遠由使用者本人在 PTT 操作**，本程式不執行也不判定。
- **PTT 標題提示／編輯區**：PTT 發文流程中的「標題」輸入提示與其後的文章編輯畫面。注意這與 Windows 視窗標題列（瀏覽器分頁標題）是兩回事，本文分別稱「**PTT 標題欄**」與「**視窗標題列**」。
- **Payload**：最終渲染後實際要送入 PTT 的「完整標題」與「完整內文」。

## 1. 目的與範圍

### 1.1 產品定義

供**個人單一使用者**使用的桌面工具：從文章 URL 擷取資料，整理成可編輯草稿，加上個人心得與簽名檔，檢查 PTT 格式與看板規則，預覽並人工確認後，協助把內容**遞送**到使用者已自行登入並開啟的 `https://term.ptt.cc/` 視窗（剪貼簿，或 Windows UI 自動輸入）。保留草稿、佇列與歷史，所有資料存於本機。

### 1.2 非目標

- 不自動登入、不保存 PTT 帳號／密碼／Cookie／Token。
- 不自動發文、不自動存檔、不執行任何送出或等效操作；不自動發布測試文章。
- 不自動重試、不自動重送、不在發文結果不明時續行。
- 不是瀏覽器外掛；不修改瀏覽器或 `term.ptt.cc` 頁面。
- 不直接連線 PTT 伺服器（不自建 telnet／SSH／WebSocket 連線）。
- 不繞過 CAPTCHA、雙因素驗證、平台安全措施、速率限制或看板規則。
- 不用於大量發文、洗版或操縱討論；不偽造作者、來源或事實。
- 不保證能擷取所有網站，不保證自動判定板規、著作權或重複。
- P2（不在 v1.0）：RSS 監控、Telegram 通知、AI 摘要、多帳號、雲端同步。

### 1.3 核心安全原則（SP）

| 編號 | 原則 |
|------|------|
| SP-01 | **不自動登入。** 使用者自行登入並開啟終端機。 |
| SP-02 | **不自動執行最終送出。** 程式碼層級不得存在存檔、發文、離開編輯器、確認送出或等效操作的路徑（見 FR-501、AT-SAF）。 |
| SP-03 | **結果不明即停，不自動重送、不自動重試。** |
| SP-04 | **內容一致**：預覽、複製、填入、雜湊使用同一渲染結果。 |
| SP-05 | **狀態不明即停**（模式 B）：無法可靠辨識視窗、焦點或畫面狀態時，停止並建議改用剪貼簿。 |
| SP-06 | 不儲存任何 PTT 憑證；日誌與備份不含認證資料。 |
| SP-07 | UI 不自動搶焦點、置頂或彈出非必要視窗。 |
| SP-08 | **測試不得造成真實發文**；自動化測試只對本機假終端機。 |
| SP-09 | 使用者逐篇明確確認；不提供無人值守發布。 |
| SP-10 | 沒有證據的技術假設不得寫成事實（標【待驗證】）。 |

## 2. 背景、已知事實與假設

### 2.1 使用情境

使用者每日閱讀新聞或網路文章，欲轉貼到 PTT 某看板（含整理媒體來源、記者、標題、內文、連結與個人心得、簽名檔）。目前手動整理與在終端機編輯費時、易有編碼／換行／格式錯誤。

主要流程：

1. 貼上 URL → 擷取 → 建立草稿。
2. 編輯來源欄位、內文、個人心得；選看板、模板、簽名檔。
3. 系統正規化、檢查、預覽；使用者確認。
4. 加入發文佇列。
5. 使用者在 `term.ptt.cc` 自行登入並進到看板的發文標題提示。
6. 以模式 A（複製→使用者自行貼上）或模式 B（程式輸入到編輯畫面）遞送標題與內文。
7. **使用者自行檢查、存檔、發文**。
8. 使用者回報結果（已發／放棄／不確定）；系統記入歷史。

### 2.2 已觀察事實（O）

觀察方式：2026-10-15 對 `https://term.ptt.cc/` 公開靜態檔案的 HTTP GET 與靜態閱讀（未登入、未連線 WebSocket）。入口 JS 檔 `assets/index-WD38Ce5v.js`，571,809 bytes，SHA-256 `cf0c96076510e1e879547a395f0c16961f226784e877a89d0c0da0a9d6766271`。**站台可能隨時改版，這些觀察不保證持續成立。** 詳細證據見 PHASE0_AUDIT §9。

| 編號 | 觀察 | 對需求的意義 |
|------|------|--------------|
| O-01 | 前端預設以 **HTML5 Canvas** 繪製畫面（偏好 `useCanvasEngine` 預設為真），並有可關閉的設定項 | 畫面文字預期不在 DOM；不得假設可用一般 Windows 控制項讀取（FR-504） |
| O-02 | 網頁標題為「批踢踢實業坊」；收到 bell 時標題會加上「🔔 」前綴 | 視窗標題列比對須容許前綴（FR-503） |
| O-03 | 前端以 WebSocket（子協定 `telnet`）連 `wss://ws.ptt.cc/bbs` | 本產品**不**使用（非目標）；僅說明終端機為網頁實作 |
| O-04 | 前端文案含「建議行長 78 字元（送出時自動換行）」等字串 | 行寬參數保守預設 78（V-05 實測） |
| O-06 | **新聞來源版型高度異質**（2026-10-15 對 19 個台灣媒體／內容網站各一篇文章的單次 GET 觀察，見 TEST_CORPUS §3）：多數為伺服器端渲染且含 OpenGraph；多數但非全部有 JSON-LD 文章節點（觀察到 ETtoday 的 JSON-LD 為無法解析的壞 JSON）；發布時間、作者欄位在多個網站缺失或需從非標準位置取得（**多家媒體的 meta author 其實是機構名或社群網址，不是記者**）；Medium、Dcard 對一般 GET 回 403；Facebook 等為登入牆／前端渲染（無 JS 時可見文字極少） | 通用解析單獨不足以達到 M1 要求；需站台規則＋結構化資料＋完整性判定＋優雅失敗（FR-104、109–111）。此為單次單篇觀察，**不代表各站穩定行為** |
| O-05 | 前期稽核靜態閱讀（同一 bundle 雜湊；**本次未逐條重驗**）顯示：貼上路徑會把換行轉 `\r`、可能啟用「長文自動換行」外掛；無法以 Big5 編碼的字元被**靜默替換**；輸入以分塊與流量控制送出 | 模式 A 貼上／模式 B 輸入都可能經此路徑；複製前必須用同規則檢查（FR-402）；實際行為屬 V-04 |

### 2.3 假設與限制

- 單一 Windows 使用者、單一 PTT 帳號、單機使用。
- 使用者以 Chrome／Edge／Firefox 之一開啟 `term.ptt.cc`；視窗由使用者自行管理。
- 目標平台：Windows 10 22H2／Windows 11，x64；高 DPI（100–200%）。**【待確認】Q-10**
- 站台、PTT 板規、PTT 編輯器行為皆可能改變；本程式把它們視為**可設定、可驗證、可過期**的資料。
- 著作權與轉載：本文僅作需求面提醒，**不構成法律建議**，實際問題須諮詢專業人士。**【待確認】Q-13**

### 3.2 M1 範圍（最低驗收要求）

核心流程（每一步都必須在 M1 實際可用）：

1. 使用者貼上文章 URL。
2. 程式自動解析可取得的文章資料。
3. 擷取**標題、媒體來源、原文 URL、作者／記者、發布時間、文章內文**；**無法取得的欄位必須明確標示「未取得」**，不得補造。
4. 使用者可修改解析結果，並輸入個人心得。
5. 程式依模板產生完整 PTT 文章草稿。
6. 顯示完整預覽；提供格式檢查、草稿儲存、**全文複製**。
7. 使用者自行把文章貼入 PTT；**程式不得自動送出**。

M1 必須同時具備：
- **可擴充的解析器架構**：區分通用解析與特定網站解析，**不得把所有來源寫死在單一解析函式內**（FR-109）。
- **內文完整性判定**：**成功擷取標題不等於成功擷取全文**；任何來源的「成功」判定必須包含內文完整性（FR-110）。
- **覆蓋多種情境**：多種網站版型、動態網頁、解析失敗、缺少欄位、中文編碼、文章重複、內文不完整（驗收見 AT-EXT、AT-M1）。
- **可重複執行的解析測試與測試 URL 清單**（FR-115、[TEST_CORPUS.md](TEST_CORPUS.md)）。
- **每個來源的支援範圍與驗收結果有明確紀錄**（FR-114）。

M1 **包含**：**單一全域簽名檔文字欄位**（編輯、儲存、套用；FR-304，決策 4）、內建預設模板、基本確認與雜湊。
M1 **不含**：**多組簽名檔**與簽名檔優先序（FR-301／302，M2）、**進階模板**（模板管理，M4）、看板規則 UI、發文佇列、歷史、備份還原 UI、Portable 封裝（Phase 1 spike 驗證可行性，正式封裝在 M2）、模式 B。

### 3.3 M1 通過條件（閘門 G-M1）

全部成立才算通過：

0. **校準完成**：[GOLDEN_SPEC.md](GOLDEN_SPEC.md) §8 的校準已完成、使用者已核准並凍結 `metrics_v1` 與門檻（初始值：文字相似度 ≥ 95%、差異比例參考 ≤ 3%）。**在此之前，所有比對結果只是校準資料，不得宣稱通過。**
1. **完整流程**：對**規劃支援的每個來源**（§3.4 的 Tier A，以及使用者追加者）完成「解析 → 人工修正 → PTT 文章組合 → 預覽 → 檢查 → 複製」。
2. **全文而非僅標題**：每個 Tier A 來源以**狀態為 `VERIFIED`（已人工核對）的黃金檔**做全文比對（計算方式、適用欄位、衝突處理見 GOLDEN_SPEC §4～§7）；**未通過人工核對的黃金檔不得當作正確基準**；不得以「取得標題」代替。
3. **多情境覆蓋**：§3.2 所列七類情境各至少有可重複執行的測試案例並通過（ACCEPTANCE_TESTS M1-020～M1-026）。
4. **來源支援紀錄**：每個來源的「支援層級、已知限制、最後驗證日期、測試結果」寫入來源支援矩陣（FR-114；初版見 TEST_CORPUS §6，目前全部為「未建立／未執行」）。
5. **安全底線**：SP-01～SP-10 全部適用；M1 無遞送自動化、無任何自動送出（AT-SAF 的靜態檢查在 M1 即啟用）。
6. **回歸測試可重複**：離線快照測試在乾淨環境一鍵重跑，結果與紀錄一致（FR-115）。

### 3.4 來源支援層級（Tier）

| Tier | 定義 | M1 要求 |
|------|------|---------|
| **A（完整支援）** | 有站台規則或結構化資料可穩定取得全部六項欄位（缺失欄位可明確標示，如該站不提供作者）與完整內文 | 每來源 ≥ 2 篇離線快照；其中 **≥ 1 份為 `VERIFIED` 的保留快照黃金檔（且至少 1 份由使用者本人核對）並通過比對**；其餘快照的黃金檔未 `VERIFIED` 者僅為暫行回歸；列為 M1 閘門 |
| **B（部分支援）** | 通用解析＋結構化資料可得標題／連結／部分欄位；內文可能需人工補全；完整性判定須正確發出警告 | 每來源 ≥ 1 篇快照；欄位狀態與警告正確；不要求全文一致 |
| **C（優雅失敗）** | 登入牆、反爬、純動態渲染等無法靜態取得 | 必須「說明原因、不繞過、引導改用手動輸入（FR-112）」；不得假裝成功 |

**真實來源清單（決策 2，已實際連線驗證）**：20 個來源（Tier A 12、Tier B 8）、39 篇文章，附來源名稱、文章標題、URL、取得日期與測試用途，見 [TEST_CORPUS.md](TEST_CORPUS.md) §3。Tier C 目前只有首頁類探針，**文章 URL 待蒐集**。清單待使用者最終確認（Q-21）。

## 4. 功能需求（FR）

> 格式：**需求**｜優先級｜說明｜驗收（ACCEPTANCE_TESTS 群組）。「必須」＝強制；「應」＝建議；「可」＝可選。

### 4.1 URL 輸入與資料擷取

**FR-101 URL 輸入與驗證**｜P0｜驗收：AT-EXT
- 接受單一 HTTP／HTTPS URL；拒絕其他協定與格式錯誤 URL，顯示原因；畸形 URL（如不完整的 IPv6 括號）必須回報驗證失敗，**不得拋出未處理例外**。
- 保留使用者輸入的原始 URL（`source_url`）。

**FR-102 URL 正規化（Canonical URL）**｜P0｜驗收：AT-EXT
- 必須：scheme／主機名稱小寫、移除 fragment、移除預設 port、query 參數依 key 穩定排序、無值參數維持原樣、percent-encoding 正規化不改變語意。
- 移除已知追蹤參數（如 `utm_*`、`fbclid`、`gclid`），不得無條件移除所有 query；可能是文章識別的參數須保留。
- Canonical URL 不得含 userinfo；原始 URL 含 userinfo 時須警告，且不得寫入日誌與歷史顯示。
- 規則必須可單元測試，並用於重複比對（FR-604）。

**FR-103 受限抓取**｜P0｜驗收：AT-EXT
- 必須設定且可調整：逾時（暫定 15 秒）、回應大小上限（暫定 5 MB）、重新導向上限（暫定 5 次，每次重新驗證為 HTTP／HTTPS）、同網域最小請求間隔（暫定 2 秒；**若站台 `robots.txt` 宣告 `Crawl-delay` 則取兩者較大值**，語料觀察到 iThome 為 10 秒、維基百科為 5 秒）。
- 只處理 `text/html`、`application/xhtml+xml`；其餘拒絕並說明。
- 字元編碼判定優先序：HTTP 標頭宣告 > HTML `meta charset` > BOM > 自動偵測（僅前述皆缺才用）；不得以偵測結果覆蓋明確有效的宣告。
- User-Agent 必須誠實標示本工具，不得偽裝成特定瀏覽器以規避反爬。
- 應檢查 robots.txt；若目標路徑被禁止，須警告，是否繼續由使用者**針對單篇**決定。
- 不帶使用者 Cookie／登入資訊；只發出 GET；抓取內容不在程式內執行任何腳本、不載入圖片或 iframe。
- 付費牆、登入限制、反爬或網站錯誤須回報可理解的原因，**不得嘗試繞過**。

**FR-104 資料擷取策略**｜P0｜驗收：AT-EXT
- 三階段可替換流程：① JSON-LD／OpenGraph／meta；② 外部宣告式站台規則（YAML 或 JSON，**僅安全解析、不得執行程式碼**）；③ 通用正文抽取作為 fallback。
- JSON-LD 必須依 `@type` 選取文章型節點（如 NewsArticle、Article、BlogPosting），支援 `@graph`；**不得**以 Organization、WebSite、BreadcrumbList 等非文章節點的 `name` 當作標題或作者。
- 站台規則網域比對為「完全相等或子網域」（`example.com` 匹配 `www.example.com`，不匹配 `notexample.com`）。
- 規則逐項驗證型別與選擇器語法；單一規則錯誤只停用該規則並回報檔名與原因，不得影響其他規則或造成崩潰。
- 作者／日期選擇器必須指向對應元素，不得以正文段落代替作者。
- 內建站台規則須附離線測試快照與最後驗證日期；未經驗證的規則預設停用。**要優先支援哪些網站【待確認】Q-12／Q-21；各網站覆蓋率【待驗證】V-15。**
- 擷取與顯示一律以純文字處理，不以 HTML 渲染。
- 結構化資料損壞（例如無法解析的 JSON-LD）必須被隔離：該來源降級，不得使整個解析失敗或崩潰（O-06 已觀察到實例）。
- 解析器的組織方式見 FR-109；M1 起即須符合。

**FR-105 擷取欄位與缺漏處理**｜P0｜驗收：AT-EXT
- 應嘗試取得：標題、來源網站名稱、原文 URL、記者／編譯者、發布日期、內文、可辨識的圖片 URL。
- 取不到的欄位**明確標示「未知」**，不得自行補造；`fetch_status` 區分 SUCCESS／PARTIAL（缺標題或內文等必要欄位）／FAILED。
- 擷取結果（Article）唯讀保留擷取當下狀態；使用者後續編輯只影響草稿（FR-201）。

**FR-106 擷取失敗紀錄與重新擷取**｜P0｜驗收：AT-EXT
- 擷取失敗也必須保存一筆 Article（FAILED＋原因）；重新擷取建立**新**的 Article，不覆寫舊紀錄。

**FR-107 PTT 網頁版文章來源**｜P0（M1，Tier A 來源之一）｜驗收：AT-EXT
- 支援解析 `www.ptt.cc` 網頁版文章為草稿來源：移除 metaline 與推文，保留換行；作者、看板、日期對應到來源欄位。*（「PTT 相關來源」的既有需求；對其他 PTT 鏡像站不在範圍。）*

**FR-108 批次 URL**｜P1｜驗收：AT-EXT
- 一次加入多個 URL，逐篇顯示擷取狀態；單篇失敗不影響其他；批次不代表批次確認或批次遞送；遵守 FR-103 的同網域間隔。

**FR-109 可擴充的解析器架構**｜P0（M1）｜驗收：AT-EXT、AT-M1
- **分層**：(1) 文件載入（抓取、解碼、DOM）(2) **解析器註冊表**：依 URL（網域／路徑樣式）與文件特徵選出適用的解析器 (3) **解析策略**，依序嘗試並**逐欄位**合併：站台規則 → 結構化資料（JSON-LD／OpenGraph／meta／內嵌狀態 JSON）→ 通用正文抽取 (4) 清理 (5) 完整性分析（FR-110）(6) 產出解析結果（FR-113）。
- **區分通用解析與特定網站解析**：通用策略不含任何網站專屬常數；網站專屬知識只存在於「站台規則（宣告式檔案）」或「受版本管理、獨立檔案的專屬解析器外掛」，後者僅限本專案內建，不接受使用者提供的程式碼。
- **新增一個來源不需修改核心解析流程**：只需新增一份站台規則（＋離線快照＋黃金檔）；僅當宣告式規則不足時才新增專屬解析器外掛，且外掛不得改動其他來源的行為。
- 逐欄位保留**來源策略**與**信心／狀態**（FR-113），合併規則（哪個策略優先於哪個欄位）為資料驅動、可測試。
- 任一策略的例外必須被隔離並記錄，不得使整體解析崩潰；策略失敗回退到下一個策略。
- 解析是**純函式式**：同一份輸入文件＋同一份規則 → 同一份輸出（利於離線回歸測試）。解析器**不執行網頁腳本、不連網**（連網僅發生在文件載入層）。

**FR-110 內文完整性判定**｜P0（M1）｜驗收：AT-EXT、AT-M1
**成功擷取標題不等於成功擷取全文。** 解析結果必須帶 `body_status`：
- `COMPLETE_LIKELY`（可能完整）、`SUSPECT_PARTIAL`（疑似不完整）、`INSUFFICIENT`（明顯不足）、`UNKNOWN`（無法判定）。**不使用「確定完整」**——程式無法證明完整。
- 判定訊號（組合使用，皆可測試，門檻為參數【待驗證】V-20）：內文長度與段落數；與結構化資料（如 JSON-LD `articleBody`、`og:description`）交叉比對；是否含截斷標記（如「展開全文」「繼續閱讀」「請登入／訂閱」「下一頁」）；分頁連結（`rel=next`、「第 1/N 頁」）；結尾是否為突然中斷；內文／全頁文字比；候選區塊是否為導覽或推薦清單。
- 任何非 `COMPLETE_LIKELY` 狀態：UI 以明顯警告呈現原因，並提示使用者在原網站核對、手動補全或改用手動輸入（FR-112）；**M1 驗收不得把此類結果計為「全文擷取成功」**。
- **確認閘門**：`body_status` 為 `SUSPECT_PARTIAL`／`INSUFFICIENT`／`UNKNOWN` 時，草稿「確認」前須使用者明確勾選「已對照原文核對內文」（記入稽核事件）；`INSUFFICIENT` 且內文為空者不得確認。
- 分頁文章：偵測到分頁時，M1 至少標示 `SUSPECT_PARTIAL` 並指出頁數；**是否自動抓取後續頁【待確認】Q-26**（預設不自動抓取，避免額外請求；列為 M4 候選）。

**FR-111 動態網頁與登入牆處理**｜P0（M1）｜**【待驗證】V-19**｜驗收：AT-EXT、AT-M1
- 解析器必須能**偵測**「靜態 HTML 幾乎沒有可見正文」的前端渲染外殼（可見文字極少、存在前端框架根節點或內嵌狀態資料等特徵），以及登入牆／年齡確認／付費牆／反爬挑戰（如 HTTP 403 或挑戰頁）。
- 若內嵌狀態 JSON（例如 `__NEXT_DATA__` 之類）**以靜態方式**即含文章內容，可作為結構化資料策略取用；**不執行腳本**。
- 否則回報 `FETCH_BLOCKED`／`NEEDS_JS`／`LOGIN_REQUIRED` 等明確原因，**不嘗試繞過**，並引導使用者改用手動輸入（FR-112）。
- 是否引入內嵌瀏覽器引擎渲染動態網頁，屬 P2 候選，且與「不執行網頁腳本」原則衝突，**【待確認】Q-22**；M1 不含。

**FR-112 手動輸入備援**｜P0（M1）｜驗收：AT-M1
- 任何解析失敗、部分解析或使用者不信任解析結果時，可直接於草稿編輯器**手動貼入／輸入**標題、來源、連結、作者、日期與內文，並可保存來源 URL；完整流程（組合、預覽、檢查、複製）不因解析失敗而中斷。
- 手動輸入的欄位在狀態中標示為「使用者提供」。

**FR-113 解析結果、逐欄位狀態與人工修正**｜P0（M1）｜驗收：AT-M1
- 解析結果逐欄位（標題、媒體來源、原文 URL、作者／記者、發布時間、內文、圖片 URL）呈現：**值、狀態**（已取得／未取得／疑似／使用者修改）、**來源策略**（站台規則／JSON-LD／OpenGraph／通用抽取／使用者）、警告。
- 未取得的欄位**明確顯示「未取得」**，不得留空白當作已取得，不得補造；使用者可手動填寫，狀態轉為「使用者修改」。
- 使用者所有修改只寫入草稿；Article 原始解析結果保持唯讀（FR-105、201）。
- 顯示解析使用的規則（網域規則名稱與版本）與解析耗時，便於回報問題。

**FR-114 來源支援矩陣與紀錄**｜P0（M1）｜驗收：AT-M1
- 維護「來源支援矩陣」：來源、Tier（§3.4）、欄位支援範圍、已知限制、規則版本、最後驗證日期、各快照的測試結果。
- 矩陣由回歸測試產生或核對（FR-115），不得僅憑人工宣稱；M1 閘門以矩陣內容為準。
- 程式內亦提供「此網站的支援程度」提示（Tier A／B／C／未知）。

**FR-115 可重複執行的解析回歸測試**｜P0（M1；開發需求）｜驗收：AT-M1、AT-GLD
- 測試語料包含：**離線快照**（保存原始 HTTP 回應位元組與標頭、最終 URL、取得日期；另含正文與截圖，見 FR-116）＋**黃金檔**（人工核對的預期欄位與內文，格式與狀態見 GOLDEN_SPEC）。離線測試**完全不連網**，結果可重複。
- 另設**線上抽查**（對清單 URL 實際 GET）作為站台改版預警，**不納入閘門**、不阻擋建置；預設關閉，需明確啟用（環境變數），沿用使用者既有專案的做法。
- 測試報告輸出每來源、每快照、每欄位的結果（含黃金檔狀態），並可更新來源支援矩陣（FR-114）。**測試框架必須拒絕把非 `VERIFIED` 的黃金檔用於閘門判定**，並對語料缺失明確失敗。
- 語料新增來源的流程文件化（TEST_CORPUS §10）。

**FR-116 本機網頁快照（語料取得與合規）**｜P0（M1；開發工具需求）｜驗收：AT-SNP
- 每份快照保存：**HTML**（原始回應位元組＋標頭＋最終 URL）、**正文**（擷取出的純文字）、**截圖**（全頁，作為人工核對佐證）、**來源資訊**（來源名稱、文章標題、請求與最終 URL、取得日期時間、HTTP 狀態、User-Agent、robots 判定、Crawl-delay、取得方式、測試用途、使用條款確認狀態、各檔 SHA-256）。
- **合規**：遵守網站使用條款、著作權與存取限制；只對「使用條款已由人確認」的來源擷取；遵守 `robots.txt`（Disallow 則略過並記錄）與 `Crawl-delay`；誠實 UA；每 URL 單次 GET；**不登入、不帶 Cookie、不繞過登入牆／付費牆／反爬**；遇 403／挑戰頁／登入牆即停止並記錄（該情境即 Tier C 測試資料）。
- **用途限制**：僅供本機測試；**不公開散布、不隨發行版打包、不用於訓練模型**；版控規則（原始頁面、正文、截圖不進版控，只入索引與雜湊）沿用使用者既有專案處理版權樣本的做法。
- 截圖取得方式（人工瀏覽器截圖或自動化）**【待確認】Q-31**。
- 語料工具由使用者啟動，**不是產品執行階段功能**。

**FR-117 全文比對與黃金檔**｜P0（M1；開發需求）｜驗收：AT-GLD、AT-CAL
- 比對指標、適用欄位、衝突處理規則、黃金檔狀態機與人工核對流程依 [GOLDEN_SPEC.md](GOLDEN_SPEC.md)。初始值：**文字相似度 ≥ 95%、差異比例參考 ≤ 3%**（【待校準】）。
- **只有 `VERIFIED`（人工核對通過）的黃金檔是正確基準**；程式或 AI 產生的草稿、開發者自行比對不算人工核對。
- 每個來源至少抽核一篇（逐項核對：標題、作者、日期、正文、其他必要欄位），其中至少一篇由使用者本人核對。
- 先校準（GOLDEN_SPEC §8）、經使用者核准後凍結門檻；凍結前的比對結果不得用於宣稱通過。

### 4.2 草稿、心得

**FR-201 草稿欄位與資料隔離**｜P0｜驗收：AT-DRF
草稿獨立保存下列可編輯欄位（由 Article 帶入時須先經 FR-401 正規化；標題為單行，換行轉空白）：
目標看板、分類框、標題、來源網站名稱、記者／編譯者、發布日期（預設不渲染）、原文連結、文章內文、**個人心得**（FR-206）、模板、簽名檔選擇（模式＋ID＋快照）。
- 修改草稿欄位不得改動 Article 原始紀錄。
- Article 與 Draft 為一對多；可不經擷取直接「新增空白草稿」。

**FR-202 草稿儲存與編輯**｜P0｜驗收：AT-DRF
- 手動儲存與自動儲存（防抖，暫定 800 ms；僅在正規化後內容**確實改變**時寫入並遞增版本）。
- 程式異常結束後，最近一次已儲存內容不得遺失（FR-701）。

**FR-203 草稿列表與搜尋**｜P0｜驗收：AT-DRF
- 列表可依更新時間、看板、狀態排序／篩選；關鍵字搜尋涵蓋標題、內文、來源、心得（簡單子字串比對即可；全文索引為 P1，FR-606）。

**FR-204 草稿刪除與封存**｜P0｜驗收：AT-DRF
- 從未進入佇列、也沒有遞送紀錄的草稿可刪除（需二次確認）。
- 已有佇列項目、遞送嘗試或歷史的草稿**不得硬刪除**，只能封存（`archived_at`），並可還原封存。

**FR-205 複製為新草稿**｜P0｜驗收：AT-DRF
- 任何草稿可複製為新草稿（記錄 `cloned_from_draft_id`，狀態 DRAFT），並觸發本機重複檢查（FR-604）。

**FR-206 個人心得**｜P0｜驗收：AT-DRF、AT-BRD
- 心得為獨立欄位，不與擷取內文共用。
- 字數計算規則明確（預設：去除所有空白字元後的字元數，可設定），有測試案例。
- 看板設定了最低字數時才檢查；規則未知（NULL）顯示「未確認」，不得假裝通過；0 代表使用者確認無要求（FR-312）。
- 心得變更必須使先前確認失效（FR-207）。

**FR-207 版本與確認失效**｜P0｜驗收：AT-CFM
- 任何影響渲染結果的欄位（含看板、分類框、標題、內文、來源欄位、心得、模板、簽名檔選擇／快照）發生「正規化後的實際變更」，草稿版本加一；若原為 CONFIRMED 則轉 INVALIDATED，且其 WAITING 佇列項目自動移出佇列並記錄原因。
- 未實際變更內容的儲存不得使確認失效。

### 4.3 簽名檔

**FR-304 M1 單一全域簽名檔文字欄位**｜P0（M1）｜驗收：AT-SIG（SIG-M1-xxx）
- 系統提供**一個**全域簽名檔文字欄位：可**編輯**（多行文字）、**儲存**（寫入資料庫設定，隨備份保存）、**套用**（每篇草稿可選擇「套用／不套用」；預設值為「有簽名檔文字時套用」，可設定）。
- **不含**：多組簽名檔、全域預設切換、看板／模板預設、優先序、刪除引用限制（皆屬 M2，FR-301／302）；**不含進階模板**。
- 渲染（沿用 FR-303，INLINE 為預設且待 V-06）：套用時在內文後渲染系統產生的單獨一行「--」分隔線與簽名檔文字；不套用時完全不渲染（含分隔線）；簽名檔文字為空則不渲染。
- **快照**：每次影響渲染的草稿儲存時，把當時的簽名檔文字與套用狀態存入草稿快照；之後修改全域簽名檔文字**不改變既有草稿**，也不使已確認草稿失效；提供「重新套用目前簽名檔」動作（視為草稿編輯，遞增版本）。
- **檢查**：簽名檔文字經 FR-401／402（控制字元、不可編碼字元）檢查；不得含單獨一行的「--」；行數上限為參數（暫定值【待驗證】V-06）。
- **M2 遷移**：升級到多組簽名檔時，既有全域簽名檔文字自動轉為一筆名為「預設」的 SignatureProfile 並設為全域預設；既有草稿快照不變；遷移須有測試與遷移前自動備份。

**FR-301 簽名檔管理**｜P0（M2；M1 以 FR-304 代替）｜驗收：AT-SIG
- 新增、編輯、刪除、預覽、設定「全域預設」（最多一個，以資料庫唯一索引保證）。
- 簽名檔文字同樣經 FR-401／402 檢查；不得含單獨一行的「--」（會與分隔線衝突）。
- 刪除：若仍被**未結案草稿**（非 POSTED／ABANDONED 且未封存）、模板或看板設定引用，須阻止刪除或要求明確解除引用；僅被已結案或已封存草稿引用時允許刪除，該草稿的簽名檔 ID 設為空、**快照內容保留**。不得靜默改用其他簽名檔。

**FR-302 簽名檔選擇與優先順序**｜P0（M2）｜驗收：AT-SIG
- 每篇草稿選擇模式：DEFAULT（依優先序）／SPECIFIED（指定某簽名檔）／NONE（**明確不使用**）。
- 預設優先序（**【待確認】Q-04**，建議）：草稿明確指定（含明確不使用）> 看板預設 > 模板預設 > 全域預設。明確不使用不得被其他預設覆蓋。
- 快照：每次影響渲染的草稿儲存時，依優先序解析一次並保存快照；已確認草稿的渲染一律使用快照，**修改簽名檔清單不得改變既有草稿快照，也不使已確認草稿失效**。未確認的 DEFAULT 草稿提供「重新套用目前預設」動作，視為草稿編輯（遞增版本）。
- UI 顯示目前選用的簽名檔名稱與實際內容。

**FR-303 簽名檔投遞方式**｜P0（M1 起；INLINE 預設）｜**【待驗證】V-06**｜驗收：AT-SIG、AT-MAN
- INLINE：本程式在內文後渲染「--」分隔線（標記為系統產生，不受單行「--」警告）與簽名檔文字。
- SERVER_SLOT：不渲染簽名檔，改於使用者存檔時於 PTT 提示中自行選擇伺服器簽名檔。
- 兩者不得造成重複附加；INLINE 時 UI 與說明須提醒使用者存檔提示選「不加簽名檔」。預設 INLINE，待 V-06 實測後定案。

### 4.4 看板與規則

**FR-311 看板設定與選擇**｜P0｜驗收：AT-BRD
- 使用者輸入看板名稱或從已保存清單選擇（比對不分大小寫，保存時保留使用者輸入的大小寫）；發文前必須清楚顯示目標看板。
- 看板設定可保存：允許的分類框、預設模板、預設簽名檔、規則條目（FR-312）、備註。
- 系統預設資料只內建 `Test` 看板，且**不含任何假設性規則數值**。
- 「看板搜尋」僅涵蓋本機已保存清單（含匯入）。遠端看板搜尋需操作終端機，**不在範圍**。**【待確認】Q-06**

**FR-312 看板規則與可驗證性**｜P0｜驗收：AT-BRD
每條規則是一筆資料：`規則類型`（分類框必填、分類框清單、標題格式、心得最低字數、每日發文上限、最小發文間隔、其他備註）、`值`、`來源`（使用者輸入／附上板規連結或貼上板規原文）、`狀態`（未確認／已核對／過期）、`最後核對時間`。
- 規則預設「未確認」；**僅當使用者明確按下「我已核對板規」時**才記錄核對時間並轉「已核對」。程式不自動認定任何規則為真。
- 超過可設定天數（暫定 90，**【待確認】Q-16**）未重新核對者顯示「過期」。
- 心得最低字數：NULL＝未知；0＝已確認無要求；兩者行為不同。
- 系統不得宣稱規則等於最新官方板規。

**FR-313 看板規則檢查**｜P0｜驗收：AT-BRD
- 只檢查已設定的規則；每個檢查結果標明所依規則、規則狀態與最後核對時間。
- 規則未知或過期 → 結果為「未確認」（警告級），**不得顯示為通過**。
- 已核對且違反（如心得字數不足、分類框不在清單）→ 依規則設定為阻擋或警告（預設：分類框／心得字數為阻擋；其餘警告）。
- 配額／冷卻檢查見 FR-607（P1）。

### 4.5 模板

**FR-321 內建模板**｜P0｜驗收：AT-TPL
- 內建一份**唯讀、版本化**的預設模板：新聞轉貼格式（媒體來源、記者署名、完整標題、完整內文、完整連結、個人心得）；欄位順序與顯示可由模板定義；隱藏欄位不得造成資料被刪除。
- 發布日期欄位預設不渲染，僅在模板啟用時渲染。

**FR-322 模板管理**｜P1｜驗收：AT-TPL
- 新增、編輯、複製、刪除、指定預設；內建模板不可編輯／刪除。模板可設定：看板、預設分類框、標題格式、欄位順序／顯示、預設簽名檔。
- 套用或修改模板若改變最終內容，使先前確認失效。

### 4.6 內容處理、檢查與預覽

**FR-401 正規化與差異報告**｜P0｜驗收：AT-CHK
進入草稿與渲染前一律套用：
1. CRLF、單獨 CR → LF。
2. Tab → 半形空白（寬度為參數，暫定 4）。
3. **完整** ANSI／終端機跳脫序列（ESC 開頭）整段移除，不得僅移除 ESC 字元而殘留序列文字。
4. 其餘非換行 ASCII 控制字元（`\x00-\x08`、`\x0b-\x0c`、`\x0e-\x1f`、`\x7f`）移除。
5. Unicode 控制與不可見字元（C1 控制字元、零寬字元、BOM、U+2028／2029、雙向覆寫字元）移除或轉換。
- 任何自動剝除或轉換必須產生**差異報告**（種類、數量、位置），顯示給使用者，由使用者確認後才可確認草稿；不得靜默改寫。

**FR-402 編碼與字元檢查**｜P0｜**【待驗證】V-03**｜驗收：AT-CHK
- 目標編碼為 PTT 實際使用的編碼（預期 Big5 擴充，常稱 Big5-UAO）；**不得預設以 Windows cp950／Python `big5` 等同於它**。可編碼性、位元組長度與雜湊所依據的編碼須是同一個。
- 驗證前採「**保守字集**」：只放行已確認安全的字元；其餘（含 emoji、簡體字、罕用字）列為**阻擋級**，提示位置與修正方式。可提供「建議替換」並顯示差異，須使用者確認，不得自動改寫。
- 以 O-05 為由：不可編碼字元在 PTT／站台端可能被靜默替換，因此必須在複製／填入前阻擋。
- 分別顯示標題位元組長度與終端顯示寬度。

**FR-403 顯示寬度與斷行**｜P0｜驗收：AT-CHK
- 以可設定行寬（保守預設 78；斷行目標 76，【待驗證】V-05）斷行，區分位元組長度與終端顯示欄寬；East Asian Ambiguous 寬度為參數（暫定 2）。
- 不切斷任何位置（含行內）的 URL；英文單字不從中間切斷（超過行寬者除外）；處理基本中文標點避頭尾；組合與零寬字元寬度 0。
- Article 的清理結果保存「未硬換行」文字；斷行只在建立草稿內文或使用者執行「自動斷行」時套用；內容指紋以未斷行、空白正規化文字計算，**不受行寬影響**。

**FR-404 格式檢查**｜P0｜驗收：AT-CHK
對**完整最終 payload 與完整標題**做單一來源檢查（涵蓋標題、內文、心得、簽名檔、來源站名、作者、日期、連結、看板名稱、分類框，不得只檢查部分欄位）：
- 阻擋級：標題或內文為空、標題超過上限（暫定 42 bytes 含分類框，**【待驗證】V-05**，亦有其他說法）、不可編碼字元、殘留控制字元／ANSI、看板為空、已核對的看板規則違反、簽名檔投遞衝突。
- 警告級：超寬行、使用者內容單獨一行「--」、分類框不在清單、規則未確認、內容過短、疑似重複、**模板欄位缺值**（媒體／記者／日期等「未取得」的欄位）。
- **缺值欄位的渲染規則**：「未取得」是 UI 狀態，**不得**把「未知」「未取得」等字樣自動寫進文章；使用者須填入、或明確選擇「略過（隱藏）此欄」；兩者皆未做時，該欄位以警告列出且確認時需使用者逐項接受。
- 阻擋級錯誤存在時，不得確認、不得遞送。

**FR-405 單一渲染與完整預覽**｜P0｜驗收：AT-PRV
- 最終 payload 由**單一、固定**的渲染程序產生；預覽、檢查、雜湊、快照、複製、填入共用同一輸出。
- 預覽以純文字、等寬字型、終端機風格呈現（可含 80×24 模擬分頁檢視），完整顯示將送入的標題與內文；顯示位元組與寬度資訊。
- 任一相關欄位變更後預覽即時更新。

**FR-406 人工確認與內容雜湊**｜P0｜驗收：AT-CFM
- 使用者須檢視完整預覽並明確確認目標看板與最終內容；確認時保存不可變 payload 快照（標題、內文、看板、編碼、序列化版本）與 SHA-256。
- 序列化規則固定且版本化（欄位順序、編碼、換行一律 LF、空白處理），版本號保存於快照。
- 遞送前**重新渲染並重算雜湊**，與快照比對；不符 → 拒絕遞送、確認失效。
- 確認有效期（暫定 24 小時，**【待確認】Q-03**）；逾期視為失效須重新確認。
- SHA-256 只用於偵測內容變更，不得宣稱保證整體系統零錯誤。

### 4.7 遞送

**FR-501 遞送總則與結構性禁止送出**｜P0｜驗收：AT-SAF
- 兩種模式獨立：任一模式未實作、被停用或故障，另一模式照常可用；不得互相依賴才能啟動。
- 遞送元件的介面**只有**「準備標題／內文、填入標題／內文、取消」；**不存在**「送出／存檔／發布」成員，也不存在可送任意按鍵的通用入口。
- **禁止操作清單**（程式碼中不得出現於遞送元件）：`Ctrl+X`、`Ctrl+Q`、`Ctrl+Z`、`Esc`、`Tab`、功能鍵、**編輯器外的 Enter**（預設亦不代按標題後的 Enter，**【待確認】Q-02**）、存檔確認鍵（`S`／`Y` 等），以及任何非白名單組合鍵。
- 以靜態檢查與變異測試把關（AT-SAF）。
- 遞送前置條件：草稿 CONFIRMED、雜湊吻合、無阻擋級錯誤、草稿不處於 POSTED／UNKNOWN（須先人工回報，FR-602）。
- **M1 子集**：M1 的複製前置條件僅「CONFIRMED＋雜湊吻合＋無阻擋級錯誤」；`posting_status`、佇列、遞送嘗試紀錄（FR-507）與核對清單（FR-605）自 M2 生效。M1 的複製動作仍寫入應用程式日誌。

**FR-502 模式 A：剪貼簿**｜P0｜驗收：AT-CLP
- 提供「複製標題」「複製內文（含簽名檔）」「複製整篇」；建議流程步驟說明（先標題、後內文）。
- 複製前重新渲染與驗證；有阻擋級錯誤不得複製（剪貼簿不變）。
- 複製後以讀回比對確認剪貼簿內容＝渲染結果；以**狀態列／非模態提示**顯示「已複製（N 字元／M bytes）」與下一步說明，**不彈窗、不搶焦點**。
- 剪貼簿隱私：寫入時盡可能帶「排除於剪貼簿歷史／雲端同步」格式（**【待驗證】V-14**）；可選「N 秒後自動清除（僅當內容仍為本程式放入）」（預設秒數 **【待確認】Q-09**）。
- 每次複製寫入遞送嘗試紀錄（FR-507）。

**FR-503 模式 B：目標視窗辨識與焦點**｜P1｜**【待驗證】V-07、V-08、V-16**｜驗收：AT-UIA
- 只操作使用者已開啟的瀏覽器視窗：行程屬允許清單（chrome／msedge／firefox，可設定）、**視窗標題列**含「批踢踢實業坊」（容許「🔔 」等前綴，O-02）。
- 找不到、找到多個無法唯一判定、視窗最小化、視窗為系統管理員權限而本程式不是（UIPI）、使用者鎖定畫面 → 停止並說明；多個候選時**由使用者明確選取**，不得猜測。
- 標題列只反映作用中分頁：使用者切換分頁導致標題不符 → 視為失焦，停止。
- 每次輸入動作**之前**都須重驗：前景視窗＝目標視窗、標題符合、視窗仍有效；任一不符即停止，不補送。
- 支援 DPI 感知與多螢幕座標轉換。

**FR-504 模式 B：畫面狀態辨識**｜P1｜**【待驗證】V-09、V-10、V-11**｜驗收：AT-UIA
- **不得假設**終端機畫面可由一般 Windows 控制項（UI Automation 等）讀取；Canvas 渲染下文字預期不在可存取樹中（O-01）。
- 須獨立評估並以 PoC 擇一或組合（ARCHITECTURE §7）：(a) 視窗截圖＋影像辨識（模板比對／OCR）；(b) 要求使用者將站台改為 DOM 渲染後以 UI Automation 讀取；(c) 無辨識 → 僅提供模式 A 與輔助貼上。
- 預期辨識的狀態：`標題提示`（PTT 標題欄）、`編輯區（空白）`、`編輯區（非空白）`、`其他`、`無法辨識`。
- 放行規則：只有在**連續多次**取樣皆辨識為預期狀態且信心達門檻時才輸入；`其他`或`無法辨識` → 停止並提示改用剪貼簿。**寧可漏判，不可誤判為可輸入**（PoC 通過標準：誤判為可輸入 = 0，見 AT-UIA）。
- 辨識能力、準確度、對字型／縮放／DPI／配色的穩健度，全部屬待驗證；未通過 PoC 前此需求**不得實作為預設啟用**。

**FR-505 模式 B：輸入執行**｜P1｜**【待驗證】V-12**｜驗收：AT-UIA
- 一次只填一個欄位：使用者先把終端機停在 PTT 標題欄 → 程式填標題 → **使用者自行按 Enter** → 使用者確認進入空白編輯區 → 程式填內文。【待確認】Q-02：是否允許在使用者明確授權下代按標題後的 Enter（預設否）。
- 白名單操作：寫入剪貼簿＋單次貼上快捷鍵；或輸入已通過檢查的可印字元與換行（方式由 V-12 決定）。
- 輸入前後保存/還原使用者原剪貼簿內容的策略【待確認】；輸入進行中 UI 顯示明確的進行中標示（非模態、不搶焦點）。
- 結果只陳述事實（「已輸入 N 次／辨識畫面：…」），**不宣稱成功**；送達無法精確確認，須使用者目視核實。

**FR-506 模式 B：中止、中斷與降級**｜P1｜驗收：AT-UIA
- 全域中止熱鍵（組合 **【待確認】Q-18**）與偵測到使用者實體鍵盤／滑鼠輸入時暫停或中止。
- 失焦、視窗關閉／最小化、逾時、辨識失敗、剪貼簿被他人改寫 → 立即停止；**不自動重試、不自動重送、不續填**。
- 輸入開始後任何中止 → 嘗試記錄為 INTERRUPTED，草稿 posting_status 轉 UNKNOWN（FR-602）；輸入開始前的失敗才記為 FAILED。
- 閘門 G-B 未通過或模式 B 停用 → 提供「輔助貼上」：備好剪貼簿並逐步指引。

**FR-507 遞送嘗試紀錄**｜P0｜驗收：AT-QUE
- 每次遞送嘗試（含複製）寫入：草稿 ID、版本、payload 雜湊、模式、起迄時間、結果（COPIED／FILLED／ABORTED／FAILED／INTERRUPTED）、中止原因。
- **Write-ahead**：開始前先寫「started」；程式重啟時發現無結束時間者一律標 INTERRUPTED 並使草稿進入 UNKNOWN。

### 4.8 佇列、歷史與重複

**FR-601 發文佇列**｜P0｜驗收：AT-QUE
- 佇列＝使用者排序的「待發清單」（僅 CONFIRMED 草稿可加入）；支援加入、移除、上下排序、檢視。**不會自動執行、不自動推進下一篇**；一次最多一個項目為「進行中」（ACTIVE）。**【待確認】Q-15（語意以此為預設）**
- 草稿被編輯致確認失效 → 自動移出佇列並記錄原因。
- 程式重啟後佇列狀態保留。

**FR-602 發文結果人工回報**｜P0｜驗收：AT-QUE
程式**無法也不判定**發文是否成功。使用者回報：
- 「已發文」→ POSTED（可選填文章識別碼／URL、實際發文時間、備註；未填存 NULL，不寫佔位字串）。
- 「未發／放棄」→ ABANDONED。
- 「不確定」→ UNKNOWN，並顯示核對指引（到看板或個人文章列表查找標題、時間）。
- UNKNOWN 的草稿**鎖定**：不可再遞送，須先回報「已發文」「確認未發」（記錄原因並二次確認後回到 NOT_POSTED）或「放棄」。**不得自動重送。**
- POSTED 的草稿不得再遞送；如需重發相近內容，只能「複製為新草稿」（FR-205，觸發重複檢查）。
- 所有回報寫入歷史與稽核事件。

**FR-603 歷史紀錄**｜P0｜驗收：AT-HIS
- 保存：草稿 ID、來源與 Canonical URL（快照）、看板、完整標題、payload 雜湊、內容指紋、遞送嘗試、使用者回報結果、識別碼、各時間點。
- 列表與單筆詳情檢視；歷史不因刪除／封存草稿而遺失。

**FR-604 本機重複檢查**｜P0｜驗收：AT-HIS
- 以 Canonical URL、標題及內容指紋交叉比對本機 Article、未封存草稿與歷史（POSTED／UNKNOWN）；來源指紋與發布指紋分別比對。
- 疑似重複時列出比對依據、該筆狀態與看板，要求使用者決定；不得僅因標題完全相同就判定重複；同一 Article 已排入其他看板時額外警告。
- 僅涵蓋本機紀錄，不代表已檢查遠端看板。比對門檻 **【待確認】Q-14**。
- **M1 範圍**：Article 與草稿層（相同 Canonical URL——含僅追蹤參數不同者、相同內容指紋、疑似轉載相同內容）於匯入時即警告；與「歷史」（POSTED／UNKNOWN）的比對於 M2 加入。

**FR-605 發文前人工核對清單**｜P0｜驗收：AT-QUE
- 遞送前顯示可設定的核對清單（預設項：目標看板已確認、板規已閱讀、看板最新文章中沒有相同新聞、已登入且在正確的發文畫面）；必須逐項勾選才可進入遞送；勾選結果記入遞送嘗試。
- 本程式**不**自動讀取看板檢查遠端重複（需操作終端機，不在範圍）。

**FR-606 歷史進階搜尋與篩選**｜P1｜驗收：AT-HIS（全文索引 FTS 可選）

**FR-607 配額與冷卻提醒**｜P1｜驗收：AT-BRD
- 依使用者設定的每日上限／最小間隔，以本機歷史計算提醒；時區可設定（預設 Asia/Taipei）；UNKNOWN 計入；僅提醒（警告級），並標示「本機歷史可能不完整」；不得宣稱符合最新板規。

### 4.9 資料、設定、備份

**FR-701 SQLite 儲存與遷移**｜P0｜驗收：AT-DAT
- 草稿、設定、簽名檔、看板、模板、佇列、歷史、稽核事件存於 SQLite；schema 有 CHECK／外鍵／必要索引；歷史相關表不得因刪除草稿而連鎖刪除。
- 時間戳以 UTC（ISO 8601）保存；Schema 版本實際用於遷移判斷；遷移前自動備份；遇到比程式新的 schema 拒絕開啟並說明。
- 儲存方案與 Portable／可移除磁碟的相容性 **【待驗證】V-02**。

**FR-702 設定與設定檔**｜P0｜驗收：AT-DAT
- 啟動用的小型設定檔 **`config\settings.json`**（資料目錄覆寫、日誌等級、UI 偏好；**沿用使用者既有專案的 `config\settings.json` 慣例**，位於程式同層，原子寫入）；其餘設定存資料庫。兩者皆不得含任何憑證。
- 提供設定畫面：行寬、標題上限、斷行參數、自動儲存、確認有效期、核對清單、剪貼簿清除秒數、日誌等級等（見 §8 參數表）。

**FR-703 備份**｜P0（手動）／P1（自動滾動）｜驗收：AT-DAT
- 使用者可一鍵產生備份（以資料庫線上備份機制取得一致性快照＋設定＋外部規則檔），檔名含 schema 版本與時間；備份**不含憑證**（本產品不存）。
- P1：自動滾動備份（份數可設定）、遷移前自動備份（P0 已要求）。

**FR-704 還原**｜P0｜驗收：AT-DAT
- 還原前驗證備份格式與 schema 版本；還原前自動備份目前資料；還原失敗不得破壞原資料；還原完成後提示重新啟動或自動重新載入。

**FR-705 匯出／匯入**｜P1｜驗收：AT-DAT
- 歷史、佇列、草稿匯出為 CSV／JSON；匯入時驗證欄位、版本與重複；匯出檔不含認證資料；不取代完整備份。

### 4.10 營運

**FR-801 錯誤日誌**｜P0｜驗收：AT-LOG
- 滾動日誌（大小與份數可設定）；每筆含時間、等級、錯誤碼、相關草稿／嘗試 ID、可操作的摘要。
- **遮蔽**：password、passwd、pwd、token、secret、api_key、session、cookie、set-cookie、authorization（含 Bearer／Basic）；多值 Cookie 整段遮蔽；遮蔽也作用於例外堆疊；記錄 URL 時移除 userinfo 與敏感 query 參數。
- 錯誤碼分類至少：URL／擷取、格式驗證、遞送（剪貼簿／視窗／辨識）、儲存、設定、系統。

**FR-802 操作狀態提示**｜P0｜驗收：AT-LOG
- 背景工作（擷取、備份）顯示進度與可取消；遞送狀態以非模態提示呈現（已複製、輸入中、已停止＋原因＋建議下一步）；錯誤訊息含原因、影響與可行處理。
- 不自動搶焦點、置頂或彈出非必要視窗（SP-07）；模式 B 進行中顯示明確的持續標示。

**FR-803 單一執行個體**｜P0｜驗收：AT-PRT
- 同一資料目錄同時只允許一個執行個體；後啟動者提示並結束；殘留鎖（程序已不存在）可偵測並接管。

**FR-804 Portable 資料位置**｜P0｜驗收：AT-PRT
- 預設目錄配置（沿用使用者既有可攜版慣例：EXE 與 `config\`、`logs\` 同層）：`config\`（設定檔）、`logs\`（日誌）、**`data\`**（資料庫與備份；本產品新增）（**【待確認】Q-01**）。啟動時做寫入測試，不可寫則提示並退回 `%LOCALAPPDATA%` 下的專屬資料夾，UI 持續顯示實際位置。位置可由 `config\settings.json` 覆寫。
- 執行基礎目錄：打包後取 EXE 所在資料夾（`sys.executable`），開發時取專案根；**不得使用 `__file__`／工作目錄推算打包後路徑**。
- 不得依賴啟動時的工作目錄；不寫入登錄檔、不需系統管理員權限。
- 偵測資料位於雲端同步資料夾或網路／可移除磁碟時警告（V-02）。

**FR-805 診斷包**｜P1｜驗收：AT-LOG
- 匯出去識別化的診斷包（日誌、版本、設定摘要）；不含文章全文，除非使用者勾選。

## 7. 狀態規則

### 7.1 草稿確認狀態（review_status）
`DRAFT` → `CONFIRMED`（使用者確認且檢查無阻擋）；`CONFIRMED` → `INVALIDATED`（影響渲染的編輯、逾期、遞送前雜湊不符）；`INVALIDATED` → `CONFIRMED`（重新確認）。

### 7.2 發文狀態（posting_status；**使用者回報，非程式判定**）
`NOT_POSTED` →（遞送）`DELIVERED` →（回報）`POSTED`／`ABANDONED`／`UNKNOWN`；`UNKNOWN` →（回報）`POSTED`／`NOT_POSTED`（確認未發，須原因＋二次確認）／`ABANDONED`。`POSTED`、`ABANDONED` 為終態（POSTED 只能複製為新草稿；ABANDONED 可複製或解除封存後編輯，**【待確認】**）。遞送嘗試被中止且已開始輸入 → `UNKNOWN`。

### 7.3 遞送嘗試結果
`STARTED` →（模式 A）`COPIED`；（模式 B）`FILLED`／`ABORTED`／`FAILED`／`INTERRUPTED`。`STARTED` 在重啟後仍存在者 → `INTERRUPTED`。

### 7.4 佇列項目
`WAITING` → `ACTIVE`（使用者開始處理，至多一個）→ `DONE`（使用者回報結果後）；`WAITING` → `REMOVED`；任何階段草稿確認失效 → `REMOVED`。

詳細轉移表與副作用見 ARCHITECTURE §6。
