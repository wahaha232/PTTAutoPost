## 1. 里程碑與階段總覽

```
Phase 0  規格與計畫（本階段）──► 使用者審核（G0）
Phase 1  基礎建設與技術 spike ───────────────┐
Phase 2  核心文字管線 ─────────────────────┤  Milestone 1（M1）
Phase 3  解析器架構與來源支援 ───────────────┤  文章 URL 解析 → 人工修正 → PTT 組稿
Phase 4  組稿 UI 與複製 ──► G-M1 ─────────────┘  → 預覽／檢查／草稿／全文複製
Phase 5  簽名檔／看板規則／確認／佇列／歷史
Phase 6  Portable 封裝／備份還原／日誌 ──► G-M2（MVP）
Phase 7  模式 B PoC（7b＝真實 PTT 人工觀察）──► G-B（Go／No-Go）
Phase 8  模式 B 實作 ──► G-M3（v1.0）
Phase 9  P1 功能 ──► M4
```

| 里程碑 | 包含階段 | 通過閘門 | 說明 |
|--------|----------|----------|------|
| **M1** | 1–4 | **G-M1** | **文章 URL 解析與 PTT 文章生成不得延後**；多來源、全文驗證、可重複測試、來源支援紀錄 |
| M2（MVP） | 5–6 | G-M2 | 完整的人工確認、佇列、歷史、Portable 封裝、備份還原 |
| M3（v1.0） | 7–8 | G-B、G-M3 | 模式 B（若 PoC 通過）；否則降級輔助貼上 |
| M4 | 9 | — | 模板管理、批次 URL、配額、匯出入、診斷包 |

**排程原則**：M1 優先且不被其他工作稀釋。模式 B PoC（Phase 7）與解析器工作互不依賴，但為了不分散 M1 的人力，預設排在 M1 之後；**Phase 7b（真實 PTT 人工觀察）需要使用者時間，可在 Phase 4 前後插入，以便及早取得標題上限、行寬、貼上行為等參數**（見 §9）。

## 4. Phase 3 — 解析器架構與來源支援（M1 核心）｜工作量 XL

**目標**：實作 SRS FR-101～115，使 M1 的「URL → 解析結果」完整、可擴充、可重複驗證。

### 4.1 子階段

| 子階段 | 內容 | 出口 |
|--------|------|------|
| **3a 架構＋通用解析** | URL 驗證與正規化；受限抓取層（逾時／大小／重新導向／間隔／robots／誠實 UA）；解碼（標頭>meta>BOM>偵測）；DOM 載入；頁面分類；解析器註冊表；策略鏈與逐欄位合併；結構化資料（JSON-LD／OG／meta）；通用正文抽取；清理；ParseResult；錯誤分類 | AT-EXT 基礎組通過（以合成夾具＋少數真實快照） |
| **3b 完整性與動態網頁** | 完整性分析（訊號、門檻調校）；CSR 外殼／登入牆／反爬偵測；內嵌狀態 JSON 策略；手動備援資料路徑；分頁偵測 | AT-EXT 完整性／動態組通過；V-19、V-20 初步結論 |
| **3.0 校準（在大量撰寫站台規則之前）** | 依 GOLDEN_SPEC §8：建立校準集（每 Tier A 來源 ≥ 1 份人工核對的試行黃金檔）→ 人類一致性（≥ 3 篇雙人標註）→ 劣化判別力（X-41）→ 解析器實測分佈 → 門檻提案 → **使用者核准並凍結 `metrics_v1`** | AT-CAL 全數；校準報告；**此前所有比對結果僅為校準資料** |
| **3c Tier A 來源（批次）** | 依 TEST_CORPUS §3.1：批次 1（中央社、自由時報、聯合新聞網、ETtoday）→ 批次 2（中時、TVBS、三立、公視 PNN）→ 批次 3（風傳媒、NOWnews、BBC 中文、PTT 網頁版）。每批：（使用條款已確認）擷取**開發快照** → 寫站台規則 → 規則凍結（版本＋日期）→ 擷取**保留快照** → 建立黃金檔並**人工核對（`VERIFIED`）** → 回歸 → 更新支援矩陣 | 每來源 ≥ 1 份 `VERIFIED` 保留快照黃金檔通過（校準後門檻；至少 1 份由使用者本人核對）；其餘為暫行回歸 |
| **3d Tier B／C 來源** | 報導者、關鍵評論網、iThome、科技新報、數位時代、天下、Yahoo 新聞、維基百科（B）；Facebook／Dcard／Medium 等（C，優雅失敗） | Tier B 欄位狀態與警告正確；Tier C 失敗原因正確且不繞過 |
| **3e 重複偵測** | Canonical 比對、追蹤參數（站台宣告）、內容指紋與相似度 | AT-EXT 重複組通過 |
| **3f 支援矩陣定稿** | 矩陣由回歸報告產生；記錄支援範圍、已知限制、規則版本、驗證日期 | 矩陣與測試結果一致（FR-114） |

### 4.2 每個新來源的標準流程（SOP）
0. **確認該來源使用條款（人）**；`terms_check: ok` 才繼續。1. 擷取 ≥ 2 篇**開發快照**（含不同版型：一般、圖輯／影音、署名位置變化、短訊）；2. 寫站台規則（宣告式）；3. **凍結規則**（版本號＋日期）；4. 擷取 ≥ 1 篇**保留快照**；5. 產生黃金檔草稿，**人工逐項核對（GOLDEN_SPEC §9.2 檢查表）→ `VERIFIED`**（至少 1 份由使用者本人核對）；6. 跑回歸（只用 `VERIFIED` 作閘門基準）；7. 規則失敗時**修規則，不得改黃金檔**（衝突規則 C3／C10）；8. 更新矩陣與已知限制；規則版本與驗證日期入檔。

### 4.3 風險與緩解
站台改版（V-21）→ 線上抽查預警；通用策略吃掉專屬需求→ 嚴格分層與 code review；黃金檔人工成本高→ 半自動產生、使用者抽核；來源過多→ Tier 分級與批次交付。

**出口（Phase 3）**：AT-EXT、AT-GLD 全部通過；**AT-CAL 完成且門檻已凍結**；Tier A 每來源有 `VERIFIED` 保留快照黃金檔且比對達標；支援矩陣初版（由報告產生）；V-15、V-19、V-20、V-22、V-26 有書面結論；未 `VERIFIED` 的黃金檔清單與其「暫行」標示已列出。

## 5. Phase 4 — 組稿 UI 與複製 → **G-M1**｜工作量 L

**目標**：把解析結果接到使用者可操作的完整流程，並通過 Milestone 1。

| 工作 | 內容 |
|------|------|
| 4.1 主視窗與匯入 | URL 輸入、背景解析、進度與取消、錯誤與降級提示 |
| 4.2 解析結果／欄位編輯 | 逐欄位值＋狀態＋來源策略＋警告；「未取得」醒目；就地編輯；手動輸入備援；完整性警告 |
| 4.3 組稿 | 個人心得、分類框、看板（M1：自由輸入＋Test）、內建模板、**單一全域簽名檔文字欄位**（編輯、儲存、草稿「套用」、快照、重新套用；FR-304、SIG-M1；**不做**多組簽名檔與進階模板） |
| 4.4 預覽與檢查 | 終端機風格純文字預覽；位元組／寬度；阻擋／警告清單與跳轉；正規化差異報告確認 |
| 4.5 草稿 | 儲存（手動＋防抖自動）、列表、基本搜尋、開啟、刪除（引用保護 M2）、複製為新草稿 |
| 4.6 確認 | 基本確認（雜湊、快照、版本）；編輯後失效 |
| 4.7 複製（模式 A） | 複製標題／內文／整篇；複製前重新渲染與驗證；讀回比對；非模態提示；剪貼簿排除格式嘗試（V-14）；日誌 |
| 4.8 重複提示 | 匯入時比對本機 Article／草稿並提示 |
| 4.9 基本日誌與狀態提示 | 滾動日誌、遮蔽、操作狀態列 |
| 4.10 **M1 驗收整備** | 彙整 AT-M1 全套；產出 `M1_ACCEPTANCE_REPORT`（每來源支援範圍與驗收結果）；人工走查：使用者在 PTT 測試看板編輯畫面**貼上**（不發文、自行放棄）並回報（V-04/V-05 初步資料） |

### 閘門 G-M1（通過條件，同 SRS §3.3）
1. 對 Tier A 每個來源完成「解析→人工修正→組稿→預覽→檢查→複製」端到端流程（自動化 UI／服務層測試＋人工走查）；
2. 全文比對達標（**非僅標題**）：以 `VERIFIED` 保留快照黃金檔、校準凍結後的門檻判定；**校準未完成則不得宣稱通過**；
3. 七類情境（多版型、動態網頁、解析失敗、缺少欄位、中文編碼、文章重複、內文不完整）各自的測試通過；
4. 來源支援矩陣與測試結果一致並已記錄；
5. 靜態安全檢查通過（無自動送出、無 PTT 連線）；
6. 離線回歸一鍵重跑結果一致；
7. 使用者完成 M1 人工走查並簽收。

## 11. 定義完成（DoD）與工作規範

- **任何 FR 完成** = 程式＋對應 AT 自動化測試通過＋文件（SRS／架構）同步＋無新增阻擋級警告。

- 所有變更需通過靜態安全檢查；不得新增未評選的依賴。
- 每階段結束交付：階段報告（做了什麼／未做／風險／下階段建議），並等待使用者核准後才進入下一階段。
