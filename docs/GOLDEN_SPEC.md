## 1. 原則

1. **黃金檔不是「程式輸出的快照」**。它是人類對照原網頁逐項核對後認定「正確」的答案；程式輸出不得直接改寫為黃金檔（§7 C3）。
2. **只有狀態為 `VERIFIED` 的黃金檔才是正確基準**；其餘狀態的比對結果只是參考，不得計入 M1 閘門（§3）。
3. **門檻先校準、後凍結**：95%／3% 是起點；校準（§8）完成並經使用者核准前，不得用它們宣稱「M1 通過」。
4. **指標必須能抓到「標題成功但全文失敗」**：因此除了百分比門檻，另有結構性防護規則（§5.4），避免長文章的 5% 容忍度吞掉整段缺漏。
5. **所有比較在固定、版本化的正規化之後進行**（§4），且正規化只用於比較，不得改動儲存的資料。

## 2. 名詞

| 名詞 | 定義 |
|------|------|
| 快照（snapshot） | 某次擷取的原始 HTTP 回應位元組＋標頭＋最終 URL＋擷取時間；另含人工附加的截圖（SRS FR-116） |
| 黃金檔（golden） | 針對**一份快照**的人工核對答案：欄位預期值、預期狀態、黃金正文、禁止出現的雜訊清單、核對紀錄 |
| G／P | G＝黃金正文（正規化後）；P＝解析器輸出正文（正規化後） |
| 人工核對 | 由**人類**（使用者，或使用者指定的人）對照原網頁與快照，逐項核對並簽核。**程式或 AI 產生的草稿、開發者自行比對，都不算人工核對** |
| 保留快照（holdout） | 在站台規則凍結**之後**才擷取、未參與規則開發的快照；用於驗收，避免對著答案調規則（§8.2） |

## 3. 黃金檔狀態機與基準資格

| 狀態 | 意義 | 可作為閘門基準？ |
|------|------|------------------|
| `DRAFT` | 由工具或開發者產出的草稿，尚未核對 | **否** |
| `DEV_CHECKED` | 開發者已自行對照，但**尚未有人工核對簽核** | **否**（僅供回歸與除錯；結果標示「暫行」） |
| `VERIFIED` | 已完成人工核對、檢查表全項通過、已簽核 | **是** |
| `REJECTED` | 人工核對發現黃金檔有誤 | 否（須修正後重新核對） |
| `DISPUTED` | 解析器與黃金檔不一致，正在重新裁定（§7 C3） | 否（裁定期間凍結） |
| `SUPERSEDED` | 被新版本取代（metrics 版本變更、黃金檔修訂） | 否（保留歷史） |

轉移：`DRAFT → DEV_CHECKED → VERIFIED`；任何狀態遇到錯誤 → `REJECTED`；`VERIFIED` 遇到爭議 → `DISPUTED` → 裁定後 `VERIFIED`（新版本）或 `REJECTED`。**測試框架必須拒絕把非 `VERIFIED` 的黃金檔用於閘門**（AT-GLD 有對應負向測試）。

**M1 閘門基準數量**：每個 Tier A 來源至少 **1 份 `VERIFIED` 且為保留快照**的黃金檔；該份中至少 1 份由**使用者本人**核對。其餘快照的黃金檔若未 `VERIFIED`，其結果僅為暫行回歸。

## 4. 比較前正規化（`N_v0`）

套用於 G 與 P 兩側，**僅供比較**：

| 步驟 | 規則 |
|------|------|
| N1 | Unicode 正規化 **NFC**（**不使用** NFKC，避免把全形／半形視為相同而掩蓋差異） |
| N2 | 換行統一為 `\n`；移除 BOM、零寬字元、ASCII／C1 控制字元（與 SRS FR-401 同一清單；換行除外） |
| N3 | 逐行：移除行首行尾空白（含全形空白 U+3000）；行內連續空白縮成單一半形空白；**刪除空行** |
| N4 | **不做**：全／半形轉換、簡繁轉換、大小寫轉換、標點轉換。這些差異視為真實差異 |

比較單位為 **Unicode code point（字元）**；段落＝正規化後的一行；正文串接以單一 `\n` 連接各段，**每個 `\n` 計為 1 個字元**。`|X|` 表示 X 的字元數。

## 5. 正文（body）比對指標

### 5.1 計算方式

令 `LCS` 為 G 與 P 的**最長共同子序列**長度（字元層級，保序）。

| 指標 | 公式 | 意義 |
|------|------|------|
| **文字相似度 S** | `S = 2·LCS / (|G| + |P|)` | 整體相似度（使用者所稱「95% 文字相似度」） |
| **召回率 R** | `R = LCS / |G|` | 黃金內容被抓到的比例；`M = 1 − R` 為缺漏比例 |
| **精確率 Pn** | `Pn = LCS / |P|` | 輸出內容屬於黃金內容的比例 |
| **差異比例 D** | `D = (|P| − LCS) / |P| = 1 − Pn` | 輸出中**多出的（雜訊）**字元占輸出的比例（使用者所稱「3% 差異比例」，初始定義如此；是否改為雙向差異見 Q-34） |
| 編輯量 E | `E = (|G| − LCS) + (|P| − LCS)` | 缺漏＋多出的總字元數（短文章用） |

**精確性要求**
- 比較一律使用**整數運算**判定門檻，避免浮點誤差：例如 `S ≥ 0.95` 以 `40·LCS ≥ 19·(|G|+|P|)` 判定；`R ≥ 0.95` 以 `20·LCS ≥ 19·|G|` 判定；`D ≤ 0.03` 以 `100·(|P|−LCS) ≤ 3·|P|` 判定。**所有門檻為「含邊界」**（≥、≤）。
- LCS 必須是**精確值**，或採「先以段落對齊、再於對齊段落內精確計算」的文件化近似，且近似誤差須在校準階段驗證不超過 0.5 個百分點（【待校準】）；實作選擇不得影響結果的決定性。

### 5.2 通過判定（初始值，【待校準】）

| 條件 | 判定 |
|------|------|
| `S ≥ 0.95` **且** `R ≥ 0.95` **且** 結構性防護全數通過（§5.4） | 通過候選 |
| 通過候選且 `D ≤ 0.03` | **PASS** |
| 通過候選但 `D > 0.03` | **PASS_REVIEW**（通過，但須人工檢視多出的內容並記錄；見 §7 C1） |
| 其他 | **FAIL** |

> 為何 `S` 與 `R` 兩者都要：只看 `S` 時，輸出若比黃金少約 8% 仍可能 ≥ 0.95；加上 `R ≥ 0.95` 才能保證缺漏不超過 5%。這是本規範對「95%」的初始解讀，列為 Q-34 待使用者確認。

### 5.3 短文章規則（`|G| < 300` 字元，【待校準】）

百分比在短文章上過於粗糙（300 字的 5% 只有 15 字，卻可能是整句話）。改用：
- 仍須 `S ≥ 0.95`、`R ≥ 0.95`、結構性防護通過；
- 另須 `E ≤ 6`，否則 **FAIL**；
- `D` 的 3% 參考改為**絕對值**：多出字元 `|P| − LCS ≤ 3` 為 **PASS**，4～6 為 **PASS_REVIEW**。

### 5.4 結構性防護（不受百分比影響，任何一項不過即 FAIL）

| 編號 | 規則 | 目的 |
|------|------|------|
| G1 | 黃金**第一個正文段落**必須在 P 中找到對應段落（段落相似度 ≥ 0.90） | 防止掉開頭（例：誤把內文起點當成第二段） |
| G2 | 黃金**最後一個正文段落**必須在 P 中找到對應段落（段落相似度 ≥ 0.90） | **防止截斷／付費牆／分頁造成的「看似接近」** |
| G3 | 黃金中任何長度 ≥ 40 字元的段落，若在 P 中找不到相似度 ≥ 0.50 的對應段落 → FAIL | 防止整段缺漏被長文章的 5% 容忍度吞掉 |
| G4 | P 中不得出現重複的整段（相同段落重複 ≥ 2 次，而黃金中只出現 1 次） | 防止巢狀區塊重複擷取 |
| G5 | P 中不得出現黃金檔 `forbidden` 清單所列的雜訊（如「延伸閱讀」「相關新聞」「責任編輯」「廣告」、推文／留言樣式、分享按鈕文字） | 雜訊即使占比很小也是缺陷 |
| G6 | 段落順序不得與黃金相反（以 LCS 已涵蓋；另檢查段落層級的倒置） | 防止版面錯置 |

段落相似度＝兩段（N 後）以同樣 `2·LCS/(len1+len2)` 計算。

## 6. 適用欄位與比對規則

「閘門」欄＝該欄位不通過即該快照 FAIL。

| 欄位 | 比對形式 | 規則 | 閘門 |
|------|----------|------|------|
| **標題 title** | **正規化後全等**（N 之後逐字相同） | 黃金檔可列 `title_forms`（等價形式清單，例如含／不含站名後綴「｜聯合新聞網」）；解析結果必須等於其中之一。**不使用 95% 相似度**：短字串的 5% 可能就是一個關鍵字（如「不」），足以改變語意。是否改用相似度見 Q-33 | ✔ |
| **媒體來源 site_name** | 屬於黃金檔 `site_name_aliases` 集合 | 例：「中央社」「中央社 CNA」皆可列為等價 | ✔ |
| **原文 URL** | `canonical_url` 全等（FR-102 的正規化） | 以最終 URL／canonical 為準 | ✔ |
| **作者／記者 author** | **姓名集合**比對 | 黃金 `author_expected`：`NAMES[...]`（站台提供，姓名拆分以「、」「，」「／」「,」「and」）、`NONE`（站台不提供）、`INFERRED_ONLY`（僅能由內文署名推定）。輸出為 `FOUND` 或 `INFERRED` 時姓名集合必須相等（`INFERRED` 另須狀態標記為推定）；輸出 `MISSING` 僅在黃金為 `NONE`（或使用者簽核允許）時通過；**機構名／網址當作記者 → FAIL** | ✔ |
| **發布時間 published_at** | **時間點**，精度到「分鐘」 | 轉為同一時區後比較；來源無時區者採黃金檔 `assumed_tz`；秒以下差異忽略；日期相同但時分錯誤 → FAIL；解析輸出 `MISSING` 僅在黃金標註「站台不提供」時通過 | ✔ |
| **欄位狀態 field status** | 與黃金 `expected_status`（FOUND／MISSING／INFERRED）**相等** | 防止把 MISSING 偽裝成 FOUND，或把推定當成站台提供 | ✔ |
| **body_status** | 與黃金 `expected_body_status` 相等 | 黃金正文為 `complete` → 必須 `COMPLETE_LIKELY`；為 `partial`（付費牆、截斷、分頁）→ **不得**為 `COMPLETE_LIKELY` | ✔ |
| **page_class／fetch_status** | 與黃金相等 | 例：動態外殼必須分類為 `CSR_SHELL` | ✔ |
| **charset_used** | 與黃金相等 | 編碼類案例 | ✔ |
| **正文 body** | §5 | | ✔ |
| 圖片 URL | 集合 Jaccard 相似度，僅記錄 | 不作為閘門 | ✘ |
| 其他必要欄位 | 由黃金檔 `extra_fields` 宣告（如分頁數、廣編稿標記、更新時間） | 宣告者即為閘門 | ✔（宣告者） |

## 7. 衝突處理規則

| 編號 | 衝突情境 | 規則 |
|------|----------|------|
| C1 | `S`、`R`、`D` 結論不一致（如 `S` 過但 `R` 不過；`S` 過但 `D` 超過 3%） | **任何閘門指標不過 → FAIL**；僅 `D` 超過參考值 → **PASS_REVIEW**（不阻擋，但該來源若半數以上快照為 PASS_REVIEW，必須修正規則才可標 Tier A 完成） |
| C2 | 欄位之間的結果不一致（如正文高分、標題錯誤） | **任一閘門欄位 FAIL → 快照 FAIL**；不得以高分欄位抵銷 |
| C3 | 解析輸出與黃金檔不同 | **不得直接以解析輸出改寫黃金檔**。黃金檔轉 `DISPUTED`，由人工回頭對照快照與原網頁裁定：解析錯 → 修規則；黃金錯 → 修黃金檔並遞增 `golden_version`、記錄修改者／時間／原因，並**重新走核對流程**（回到 `DEV_CHECKED` → `VERIFIED`） |
| C4 | 快照與線上頁面不同（站台之後改版） | **以快照為準**（快照是被測輸入）；黃金檔只對應其快照，不與線上頁面比對；線上差異交由線上抽查預警 |
| C5 | 兩位核對者意見不同 | 由使用者裁決；裁決前為 `DISPUTED`，不得作為閘門基準 |
| C6 | 門檻尚未校準凍結 | 此階段所有比對結果為「**校準資料**」，不得用於宣稱通過 |
| C7 | 黃金檔為 `DRAFT`／`DEV_CHECKED` | 結果標示「暫行」，**不計入** G-M1 |
| C8 | 同一來源有多份 `VERIFIED` 快照 | **每份都須通過**，不取平均；任一失敗 → 該來源 FAIL |
| C9 | `metrics` 或 `N` 版本改變 | 全部結果重算；舊結果標 `SUPERSEDED`；門檻需重新校準與核准 |
| C10 | 站台規則修改後，既有 `VERIFIED` 快照的結果變差 | 視為回歸缺陷；不得為了通過而修改黃金檔（回到 C3 流程） |
| C11 | 黃金檔與規則由同一人同時撰寫 | 允許，但**閘門基準必須是保留快照**（§8.2），且核對須由人類簽核 |

## 8. 校準計畫（先校準，再凍結）

目的：確認 95%／3% 與 §5 的規則在真實文章上**既不過嚴也不過鬆**，並確認指標能辨別「標題成功但全文失敗」。

### 8.1 步驟

| 步驟 | 內容 | 產出 |
|------|------|------|
| C0 | 以測試向量（§10）實作並驗證 `metrics_v0` 與 `N_v0`（單元測試先行） | 指標單元測試全綠 |
| C1 | **建立校準集**：每個 Tier A 來源 ≥ 1 篇，由人工核對成 `VERIFIED` 黃金檔（試行集） | 試行黃金檔 ≥ 12 份 |
| C2 | **人類一致性（雜訊底線）**：至少 3 篇由**兩位人工核對者獨立**標註正文，計算彼此的 `S`／`R` | 若人與人之間 `S` 低於 0.98，表示標註規則含糊（如圖說、小標、署名行是否屬正文），須先收斂標註規則 |
| C3 | **判別力測試**：對每份試行黃金檔自動產生**劣化版本**：(a) 只有標題；(b) 截斷 10%／20%／50%；(c) 刪除單一長段（≥ 40 字）；(d) 加入雜訊（延伸閱讀／推文）3%／5%／10%；(e) 段落重複；(f) 段落順序錯置；(g) 全形／半形標點替換；(h) 簡繁混入；(i) 空白差異；(j) 亂碼替代字元 | 每種劣化在 `S`／`R`／`D`／防護規則下的判定分佈 |
| C4 | **解析器實測**：以試行集的解析輸出計算 `S`／`R`／`D` 分佈；盤點「非實質差異」（圖說、全形空白、小標）決定是調整標註規則還是 `N`；每一項調整都記錄原因 | 差異分類報告 |
| C5 | **門檻提案**：依 C2～C4 提出門檻調整建議（可以維持 95%／3%）→ **使用者核准** → 凍結 `metrics_v1` | 校準報告＋核准紀錄 |

### 8.2 校準通過條件（初始）

1. **漏判率 0**：劣化 (a)、(b)≥10%、(c)、(e)、(f) 在該規則下**全部**判為 FAIL（不得 PASS／PASS_REVIEW）；
2. 劣化 (d)≥5% 必須至少為 PASS_REVIEW 或 FAIL（不得 PASS）；
3. 人與人一致性 `S ≥ 0.98`（否則先收斂標註規則）；
4. 試行集真實解析結果中，因「非實質差異」造成的誤判已逐項分類並處理；
5. 校準報告經使用者核准；核准後 `metrics_v1` 與門檻凍結，後續變更走 C9。

### 8.3 防過擬合
- 開發站台規則時使用「開發快照」；**驗收使用「保留快照」**：規則凍結（版本號＋日期寫入）後才擷取、才建立黃金檔並人工核對（建議，**Q-30**）。
- 每個 Tier A 來源至少 1 份保留快照；其黃金檔為閘門基準。

## 9. 黃金檔格式與人工核對流程

### 9.1 目錄與檔案（每份快照一個目錄；位置見 TEST_CORPUS §6）

| 檔案 | 內容 |
|------|------|
| `golden.json` | 欄位預期值與預期狀態（§6）、`title_forms`、`site_name_aliases`、`author_expected`、`assumed_tz`、`expected_body_status`、`expected_page_class`、`extra_fields`、`golden_version`、`metrics_version`、`status`（§3）、核對者與簽核、檢查表結果、修改紀錄 |

| `forbidden.txt` | 該來源常見雜訊清單（段落文字或樣式，供 G5） |

### 9.2 人工核對檢查表（逐項勾選；任何一項不通過 → `REJECTED`）

| # | 檢查項 | 核對方法 |
|---|--------|----------|
| 1 | 標題與原網頁一致（含標點） | 對照原網頁與快照截圖 |
| 2 | 媒體來源名稱正確、等價清單合理 | |
| 3 | 原文 URL 為該文章本身（不是首頁、搜尋頁、列表頁、轉址後的別篇） | 開啟 URL 確認 |
| 4 | 作者／記者：與原網頁署名一致；是否在 meta、署名列或內文首段；站台不提供時標 `NONE` | |
| 5 | 發布時間：與原網頁顯示一致（含時區假設）；更新時間與發布時間未混淆 | |
| 6 | 正文第一段、最後一段與原網頁一致 | |
| 7 | 正文段落數與原網頁一致；無缺段、無重複段 | 逐段計數 |
| 8 | 圖說、廣告、延伸閱讀、推薦、留言、分享鈕、版權聲明：已排除或已列入 `forbidden`；圖說是否屬正文已有一致規則 | |
| 9 | 分頁、付費牆、「展開全文」：已標示 `expected_body_status`；黃金正文與其一致 | |
| 10 | 字元層面：全形標點、特殊符號、中文編碼無損；無亂碼 | |
| 11 | 其他必要欄位（`extra_fields`）已核對 | |
| 12 | 快照與截圖、來源資訊（URL、取得日期、取得方式）齊全 | |
| 13 | 簽核：核對者姓名、日期、結論（PASS／REJECT）、備註 | |

**人工核對責任**（Q-24 已決議）：**每個來源至少抽核一篇**；該篇須由使用者本人逐項核對上列檢查表。
