## 0. 設計原則（來自任務書最高優先級決策）

1. **不做瀏覽器外掛**；產品是 Windows Portable EXE。
2. **兩種輸入模式獨立**：A 剪貼簿、B Windows UI 自動輸入；任一個壞了或沒做，另一個照常可用。
3. **程式永遠不發文**：沒有任何程式路徑會存檔、離開編輯器、確認送出；UI 自動輸入只是「填入編輯流程」。
4. **不確定就停**：失焦、狀態不明、逾時、斷線 → 立即停止，不自動重試、不自動重送。
5. **測試不造成真實發文**：一律對本機假終端機；真實 PTT 的觀察只由使用者在測試看板人工輔助進行。
6. **沒證據的就叫「待實測」**，寫成設定參數而不是常數。

## 1. 建議的桌面應用程式架構

### 1.1 分層（與技術棧無關）

```
┌──────────────────────────── UI（桌面視窗）───────────────────────────┐
│ 草稿 │ 簽名檔 │ 看板 │ 預覽/檢查 │ 待發清單 │ 歷史 │ 設定/備份/診斷 │
└───────────────┬──────────────────────────────────────────────────────┘
                │（背景執行緒；UI 不被網路阻塞；不搶焦點）
┌───────────────▼───────────────┐   ┌───────────────────────────────────┐
│ Application Services          │   │ Extract（擷取）                    │
│ 草稿/確認/重複檢查/待發清單   │◄──│ URL 正規化→受限抓取→JSON-LD/OG→    │
│ 結果回報/事件稽核              │   │ 站台規則(宣告式)→通用抽取→純文字  │
└───────┬─────────────┬─────────┘   └───────────────────────────────────┘
        │             │
┌───────▼───────┐ ┌───▼───────────────────────────────────────────────┐
│ Core（純邏輯） │ │ Delivery（內容送進 PTT 的方式；**介面中沒有「送出」**）│
│ 正規化/控制碼  │ │  ├ ClipboardDelivery   （Mode A）                 │
│ 編碼(UAO)/寬度 │ │  ├ UiAutomationDelivery（Mode B，PoC 通過才啟用）  │
│ 單一渲染/雜湊  │ │  └ FakeDelivery/假終端機（測試用）                  │
│ 檢查/簽名檔    │ └───────────────────────────────────────────────────┘
└───────┬───────┘
┌───────▼─────────────────────────────────────────────────────────────┐
│ Storage（SQLite；遷移；備份）  │ Infra：路徑/單一執行個體/日誌(遮蔽)    │
└─────────────────────────────────────────────────────────────────────┘
```

**關鍵結構性安全設計**：`Delivery` 介面只有 `PrepareTitle / PrepareBody / FillTitle / FillBody / Cancel`；**沒有 `Submit`、`Save`、`SendKey(key)` 這類通用入口**。Mode B 的輸入驅動只接受「白名單操作」（貼上一次、輸入已檢查過的可印字元與換行），其他按鍵在型別層就無法表達。靜態檢查（§7.3）再把關一次。

### 1.2 技術棧建議（決策 D-01，**需使用者拍板**）

稽核結果：兩條路都可行，本機工具鏈皆已就緒（Python 3.12 + PySide6 6.11.2 + PyInstaller 6.22.2；.NET SDK 9.0.317）。

| 判斷點 | Python + PySide6 | C# / .NET 9 |
|--------|------------------|-------------|
| 可重用的既有程式碼 | 無——GEM 經稽核不建議當基底；EXT 是 JS | 無——同上；LOGIN 只有部分基礎設施可借 |
| 可重用的既有「測試案例／規格」 | 皆可（語言無關） | 皆可 |
| Mode B（Win32 / UIA / 影像）能力 | `pywin32`（已裝）可做視窗/焦點/`SendInput`；影像與 OCR 需另裝套件，WinRT 需額外綁定 | 一級公民：P/Invoke、`System.Windows.Automation`、Windows.Media.Ocr、WebView2 |
| 與既有技術棧（組織規範：優先考量 C#/MSSQL 相容） | 另一套棧 | **同棧**，已有 PttAutoLogin 的 Portable 與測試範例 |
| 網頁正文抽取生態 | 成熟（`trafilatura`、`bs4`；其中 trafilatura 尚未安裝） | 較少，需評估；SRS 以宣告式規則為主、通用抽取僅是 fallback，影響可控 |
| Portable | one-folder 為佳；one-file 解壓暫存、啟動慢、易誤判 | 單檔自含（LOGIN 113 MB 實例）；需確認 SQLite 原生庫打包（待實測） |
| 切換成本 | 若 Mode B PoC 發現需要 WinRT/UIA 深度整合 → 可能需要 C# 輔助程式 | 若日後要大量文字抽取，需自行補 |

**我的建議：C# / .NET 9 + SQLite（`Microsoft.Data.Sqlite`）**；UI 以 WinForms（與 PttAutoLogin 一致、程式內建 UI）為預設，除非 Phase 1 spike 證明預覽/編輯體驗不足才改 WPF。理由：① Mode B 是風險最高且最仰賴 Windows 原生能力的部分；② 與現有技術棧、發行方式（單檔 + `Data\`）一致，維護者只需一套工具；③ 既有 Python 資產（GEM）本來就不打算沿用，Python 沒有程式碼層面的優勢。
**這與任務書「Python + PySide6 優先評估」不同**，因此列為決策而非預設。若你仍偏好 Python，本計畫其餘章節**不需改動**（模組與分層相同；§8 的封裝細節以 `PyInstaller one-folder` 取代）。

### 1.4 資料模型與狀態（SRS v1.5 提案，沿用 v1.4 §7 的精神、移除自動發文專屬部分）

- 保留：`Article`、`Draft`（含 `review_status`: DRAFT／CONFIRMED／INVALIDATED、確認雜湊與版本、簽名檔快照、`archived_at`、`cloned_from_draft_id`）、`SignatureProfile`（單一預設的部分唯一索引）、`BoardConfig`（`min_notes_length` NULL＝未知／0＝無要求；種子**只有 Test 板且不含任何板規**）、`Template`（內建唯讀）、`Settings`、`JobEvent`→更名 `Event`（僅追加）。
- 新增 `DeliveryAttempt`（取代 `QueueJob`/`PostRecord` 的送出部分）：`mode`（CLIPBOARD／UIA／FAKE）、`target_hash`、`started_at`、`ended_at`、`outcome`（COPIED／FILLED／ABORTED／FAILED／INTERRUPTED）、`abort_reason`。**write-ahead**：開始填入前先寫 `started`；程式重啟時發現無 `ended_at` 者一律標為 INTERRUPTED，且草稿進入 `OUTCOME_UNKNOWN`。
- `Draft.posting_status`（**使用者回報，程式不判定**）：`NOT_POSTED`／`DELIVERED`（已複製/填入，尚未回報）／`OUTCOME_UNKNOWN`／`POSTED_MANUAL`（使用者確認已發，可選填 AID/時間）／`ABANDONED`。
- 規則：`POSTED_MANUAL` 的草稿不得再次遞送，只能「複製為新草稿」（觸發重複檢查）；`OUTCOME_UNKNOWN` 須先由使用者回報（已發／未發／放棄）才可再遞送；編輯影響渲染的欄位 → 確認失效、對應狀態重置為 `NOT_POSTED`（但 `POSTED_MANUAL` 為唯讀）。
- 「**待發清單**」＝已確認草稿的人工排序清單，使用者逐篇手動處理，**不會自動執行**（決策 D-08）。
- 完整性：`ON DELETE RESTRICT`、CHECK 約束、時間戳 UTC、`schema_version` 實際用於遷移。

## 4. 內容準備的共同規則（兩種模式共用，先於 §5、§6）

1. **同一個渲染結果**：預覽、檢查、確認雜湊、複製、填入使用同一個字串；任何一處重算都必須與雜湊一致，否則拒絕。
2. **阻擋級錯誤**未解決 → 複製與填入按鈕停用：空標題/內文、控制字元、不可編碼字元、標題超限、使用者內容含單獨一行 `--`（警告級）、心得字數未達（已知規則）。
3. 正規化造成的任何改動（移除 ANSI／控制字元／不可見字元）→ 顯示差異報告，**使用者確認後**才能進入確認。
4. 編碼規則在 UAO 表就緒前以「保守字集」判定；規則來源與不確定性在 UI 明示。
5. 簽名檔採 INLINE（本工具渲染）或 SERVER_SLOT（存檔提示時由使用者在 PTT 選）——**待真實 PTT 觀察後定案**（Phase 2）；MVP 預設 INLINE 並在說明中提醒「存檔提示請選不加簽名檔，避免重複」。

## 5. 剪貼簿模式（Mode A）

### 5.1 實作

- 動作：`複製標題`、`複製內文`（含簽名檔）、`複製整篇`（標題＋空行＋內文，供使用者自行拆）。預設建議流程：先複製標題→PTT 標題提示貼上→進編輯器→複製內文→貼上。
- 複製前：重新渲染、重新驗證、重算雜湊；有阻擋級錯誤不得複製。
- 複製後：以讀回比對確認剪貼簿內容＝渲染結果（雜湊相同）；於**狀態列**顯示「已複製標題（N 字元／M bytes）」及一行操作說明；**不彈窗、不搶焦點、不置頂**。
- 剪貼簿隱私（待實測）：寫入時帶「不納入剪貼簿歷史／不上傳雲端剪貼簿」格式；提供可選「N 秒後自動清除（僅當內容仍為本程式放入者）」。
- 記錄：每次複製寫入 `DeliveryAttempt(mode=CLIPBOARD, outcome=COPIED)`＋`Event`；草稿 `posting_status` 設為 `DELIVERED`。
- 使用者回報：待發清單/草稿頁提供「我已發文」「放棄」「不確定」，`不確定` → `OUTCOME_UNKNOWN`（顯示核對指引）。

### 5.2 驗收（自動化＝程式可驗；人工＝需真實 PTT，由使用者進行）

| 編號 | 條件 | 方式 |
|------|------|------|
| A-01 | 複製後剪貼簿文字與預覽逐字相同（含全形標點、換行、簽名檔、長文 ≥ 10,000 字） | 自動化（Windows 桌面工作階段） |
| A-02 | 有阻擋級錯誤時複製被拒，剪貼簿**不變** | 自動化 |
| A-03 | 複製過程不彈窗、不搶焦點、不置頂 | 自動化（前景視窗不變）＋人工 |
| A-04 | 雜湊不一致（模擬渲染被竄改）→ 拒絕 | 自動化 |
| A-05 | 同一草稿 `POSTED_MANUAL` 後無法再複製；`OUTCOME_UNKNOWN` 需先回報 | 自動化 |
| A-06 | 重啟後 `DELIVERED`/`OUTCOME_UNKNOWN` 狀態保留；孤兒 `DeliveryAttempt` 標為 INTERRUPTED | 自動化 |
| A-07 | 日誌不含文章全文之外的敏感資料（本模式無憑證，確認日誌無剪貼簿原文被遮蔽規則誤傷/外洩設定） | 自動化 |
| A-P1…A-P6（**待實測，使用者在 PTT 測試看板人工完成，不發文**） | P1 標題貼上是否完整；P2 內文貼上是否掉字、折行位置；P3 全形標點/罕用字是否被替換；P4 貼上後換行是否被站台「自動換行」改寫；P5 標題上限（是否含分類框）；P6 簽名檔提示行為 | 人工，結果回填 SRS v1.5 §7.11 參數 |

## 6. Windows UI 自動輸入模式（Mode B）

**狀態：Phase 2 PoC 通過前，不進入產品。** 本節是 PoC 與實作的規劃。

### 6.1 設計（若 PoC 通過）

1. **前置條件閘門（全部成立才啟用「填入」按鈕）**：目標視窗唯一且為前景；視窗標題符合（容許 `🔔 ` 前綴）；視窗行程為允許清單（chrome/msedge/firefox）；視窗未最小化；非權限落差（UIPI）；狀態辨識結果為預期畫面（「標題提示」或「空白編輯畫面」）；草稿已確認、雜湊吻合、非 `POSTED_MANUAL`/`OUTCOME_UNKNOWN`；使用者已看過「Mode B 風險聲明」。
2. **操作白名單**：①寫入剪貼簿＋送出一次 `Ctrl+V`；②（備選）輸入已檢查過的可印字元與換行。**禁止**：`Ctrl+X`、`Ctrl+Q`、`Ctrl+Z`、`Esc`、`Tab`、編輯器外的 `Enter`、`S`、`Y`、功能鍵、任何組合鍵（除 `Ctrl+V`）。
3. **每一步前重驗**：前景視窗、標題、狀態辨識；任一不符 → 立即停止。
4. **全域中止**：全域熱鍵（預設 `Ctrl+Alt+Esc` 之類，可設定）＋偵測使用者實體輸入即暫停；UI 顯示進行中的明確標示（不搶焦點）。
5. **結果**：只回報事實（「已送出 N 次貼上；畫面辨識：…」），**不宣稱成功**；任何不確定 → `OUTCOME_UNKNOWN`；**不重送**。
6. **狀態辨識**候選（PoC 決定）：(a) 視窗截圖＋模板比對/OCR（本機已有 opencv，但 OCR 引擎待選）；(b) 使用者關閉站台「Canvas 渲染」改 DOM 模式後以 UI Automation 讀文字；(c) 不辨識、改半自動（程式只備好剪貼簿並逐步引導，使用者自行貼）。
7. 與 Mode A 完全獨立：Mode B 失敗/未啟用不影響 Mode A；兩者共用 §4 的內容準備與資料表，不互相呼叫。

### 6.2 PoC 計畫（Phase 2；**全程使用本機假終端機，不連真實 PTT**）

基礎設施：重用 EXT 的 `mock-bbs.mjs`/`tls.mjs` 概念——以**站台真實前端 bundle ＋ 本機假 BBS**，另開**獨立的暫存 Chrome 設定檔**（`--host-resolver-rules` 把 `*.ptt.cc` 導到 127.0.0.1），因此**伺服器端能精確記錄實際收到的位元組**（真值）。再加一個「誘餌視窗」集合（標題相近的記事本、其他瀏覽器分頁、不同 DPI/縮放、前景切換）。

| PoC | 目的 | 通過標準（建議，待使用者確認） |
|-----|------|------------------------------|
| B1 視窗辨識與焦點守衛 | 在誘餌視窗下只鎖定正確視窗；失焦即停 | 100 次隨機場景 **0 次**輸入到錯誤視窗；失焦後最多再送 0 個動作（因為每步前重驗） |
| B2 狀態辨識 | 分辨「標題提示／空白編輯畫面／其他」 | 跨 DPI 100/125/150%、縮放 90–125%、深/淺配色的語料庫上，**誤判為「可輸入」= 0**（寧可漏判）；漏判率 ≤ 5% |
| B3 輸入保真 | 貼上 vs 逐字 vs 分行 | 伺服器端收到位元組＝預期（繁中、全形、換行、長文 > 5,000 字）；量化站台「自動換行」外掛的影響與所需站台設定 |
| B4 中止與中斷 | 失焦/最小化/斷線/熱鍵/使用者輸入 | 每種情境皆停止、**不重送**、狀態正確（`ABORTED`/`INTERRUPTED`→`OUTCOME_UNKNOWN`） |
| B5 禁用按鍵稽核 | 低階鍵盤事件記錄 | 實際送出的鍵僅限白名單；靜態檢查通過 |
| B6 權限與環境 | UIPI（瀏覽器以系統管理員執行）、鎖定畫面、多螢幕 | 偵測到即拒絕並說明 |
| B7 防毒/SmartScreen | 未簽章 EXE＋`SendInput` 行為 | 記錄結果；不通過則於說明中提示（決策 D-11） |

**Go／No-Go**：B1、B2、B4、B5 任一不通過 → Mode B 降級為方案 (c)「輔助貼上」，不上線自動輸入。

### 6.3 真實 PTT 人工輔助觀察（Phase 2b，使用者授權後；決策 D-06）

- 使用**測試看板與非主帳號**；由使用者本人登入並操作；程式（或我）**不登入、不送出任何內容**。
- 目的：確認 A1–A6、簽名檔投遞方式、`safe` 邊界（編輯器中斷是否殘留草稿）、發文後識別碼取得方式；結果以「使用者貼回的畫面文字」為證據，回填參數。
- **不發任何測試文**；進入編輯器後由使用者自行放棄。

### 6.4 驗收（Mode B 上線條件，PoC 通過後）

B-01 前置條件閘門每項皆有負向測試（缺一不可啟用）；B-02 假終端機伺服器端位元組＝預期；B-03 狀態不符時**零輸入**；B-04 失焦/斷線/逾時→停止且無自動重送；B-05 靜態檢查證明無禁用按鍵路徑；B-06 `OUTCOME_UNKNOWN` 流程完整；B-07 全域中止熱鍵有效；B-08 人工：使用者在真實 PTT 測試看板以 Mode B 填入標題與內文（不發文）並確認內容與畫面一致。

## 7. 測試策略、錯誤處理與安全驗收

### 7.1 測試分層

| 層 | 內容 | 環境 |
|----|------|------|
| 單元 | Core（正規化、編碼、寬度、斷行、渲染、檢查、雜湊、簽名檔）、URL 正規化、簽名檔優先序、狀態轉移、重複檢查、日誌遮蔽 | 無需桌面 |
| 夾具 | 擷取：HTML 夾具（EXT 的新聞/PTT 網頁版/Big5/空殼/非 HTML/超大/重新導向）；站台規則錯誤隔離；JSON-LD @graph | 本機 HTTP 伺服器 |
| 儲存 | 遷移、約束、部分唯一索引、重啟恢復（孤兒 `DeliveryAttempt`）、備份/還原、單一執行個體 | 暫存資料夾 |
| UI/桌面 | Mode A 剪貼簿、焦點不被搶、狀態列提示 | 互動式 Windows 工作階段（標籤區分，CI 可略） |
| 假終端機整合 | Mode B PoC 與回歸（§6.2） | 本機 Chrome＋假 BBS＋誘餌視窗 |
| 封裝煙霧測試 | 全新資料夾解壓、從不同工作目錄啟動、唯讀目錄、移動資料夾後仍可用 | 本機 |
| **人工驗證** | §5.2 A-P、§6.3、§6.4 B-08 | 使用者；測試看板、非主帳號 |

### 7.2 錯誤處理原則

- **分類**（沿用 FR-015）：URL/擷取、格式驗證、遞送（剪貼簿/視窗/辨識）、儲存、設定。
- **只有「確定尚未輸入任何內容」的失敗才算 `FAILED`**；已開始輸入後的任何異常 → `INTERRUPTED`＋草稿 `OUTCOME_UNKNOWN`。
- **永不自動重試遞送**；使用者重新觸發需重新通過全部前置條件，且 `OUTCOME_UNKNOWN` 須先人工回報。
- 錯誤訊息含：原因、影響、可行處理；日誌含 attempt ID、錯誤碼、模式；遮蔽規則採 v1.4 FR-016 清單（password/token/secret/api_key/session/cookie/set-cookie/authorization、URL userinfo/敏感 query、例外堆疊）。

### 7.3 靜態安全檢查（取代外掛時期的 `check-manifest`）

建置前必跑（失敗即中止）：
1. Delivery 層原始碼中**不得出現**送出/存檔/離開相關的按鍵常數與字面量（`^X`、`^Q`、`\x18`、`\x11`、`Esc`、`VK_RETURN`…）於白名單之外；
2. Delivery 介面不得新增名為 `Submit*`/`Save*`/`Publish*`/`SendKey*` 的成員；
3. 輸入驅動程式碼只能呼叫白名單 API；
4. 專案不得引用網路客戶端到 `ptt.cc`（程式不連 PTT）；僅擷取模組可發出 HTTP GET，且須 `無 Cookie／無 Referer／先授權`（沿用 EXT 設計）；
5. 依賴清單白名單（供應鏈）。
並以**變異測試**驗證：故意加入禁用按鍵或網路呼叫，檢查必須失敗（EXT 已用此法驗證過其靜態檢查 [D]）。

### 7.4 安全驗收條件（SA；Phase 1 起即適用）

| 編號 | 條件 |
|------|------|
| SA-01 | 程式碼中不存在任何會存檔、發文、離開編輯器或確認送出的路徑（靜態檢查＋變異測試） |
| SA-02 | 程式不連線到 PTT（無 `ws.ptt.cc`／`term.ptt.cc` 的連線程式；擷取模組只對使用者貼的 URL 發 GET） |
| SA-03 | 狀態不明、失焦、逾時、斷線 → 停止；**無任何自動重試／重送路徑** |
| SA-04 | 結果不明 → 草稿鎖定，須人工回報後才可再次遞送；`POSTED_MANUAL` 不可再遞送 |
| SA-05 | 不儲存任何 PTT 帳號、密碼、Cookie、Token（資料庫、日誌、備份、匯出皆無） |
| SA-06 | 所有自動化測試使用假終端機／假視窗，不產生真實發文 |
| SA-07 | 內容在確認後被改動（雜湊不符）→ 拒絕遞送並使確認失效 |
| SA-08 | UI 不自動搶焦點、置頂、彈出非必要視窗 |
| SA-09 | 不可編碼字元／控制字元／ANSI 殘留為阻擋級，無法被略過 |
| SA-10 | 備份/匯出檔不含任何認證資料；還原失敗不破壞既有資料 |

## 8. Portable EXE 封裝與資料管理

### 8.1 形態

- **目標**：解壓即用的資料夾（內含 `PttPost.exe` 與必要檔案）＋可選單檔版；不寫登錄檔、不需安裝程式、不需系統管理員權限。
- C#：`dotnet publish`（self-contained、win-x64；單檔或資料夾）；需實測 SQLite 原生庫在單檔模式的載入。
- Python（若 D-01 選 Python）：PyInstaller **one-folder** 為主；資料路徑一律以 `sys.executable` 所在目錄計算，**不用 `__file__`**。
- **本階段不建置**；Phase 1 的第一個交付物之一是「空殼程式＋封裝煙霧測試」，以便及早發現封裝問題。

### 8.2 資料目錄

```
<exe 同層>\data\
    app.db            (SQLite；WAL 僅在本機磁碟)
    backups\          (自動滾動備份、遷移前備份)
    logs\             (滾動日誌)
    rules\            (外部站台規則 YAML/JSON；逐項驗證)
    .lock             (單一執行個體；含 PID/主機名/時間)
    portable.flag     (標示可攜式模式)
```

- **預設位置**：exe 同層 `data\`（與 SRS NFR-012 的 `%APPDATA%` 預設相反，需 SRS v1.5 修訂，決策 D-03）。
- 啟動時寫入測試；不可寫（Program Files、唯讀媒體）→ 提示並退回 `%LOCALAPPDATA%\PttPost\`，UI 持續顯示實際資料位置。
- 偵測資料目錄位於雲端同步資料夾或網路磁碟 → 警告；網路/可移除磁碟 → 關閉 WAL、`synchronous=FULL`。
- 任何路徑計算**不得依賴目前工作目錄**（AC-31：從不同工作目錄啟動讀寫同一份資料）。

### 8.3 備份、匯出、還原、升級

- 備份＝SQLite 線上備份 API 產生一致性快照＋`rules\`；檔名含 schema 版本與時間；**不含憑證**（本設計不存）。
- 還原前驗證格式與 schema 版本；先備份目前資料再還原；失敗回滾。
- 升級：替換程式檔、保留 `data\`；啟動時 `schema_version` 比對 → 較舊則**先自動備份再遷移**；較新則拒絕開啟並說明。
- 匯出 CSV/JSON（P1）：歷史、事件；不含認證資料。

### 8.4 診斷

滾動日誌（大小上限）、錯誤碼、attempt ID；「匯出診斷包」（日誌＋去識別化設定＋版本資訊，**不含文章全文，除非使用者勾選**）。

### 8.5 Portable 驗收

P-01 全新資料夾解壓即可啟動；P-02 從任意工作目錄啟動結果一致；P-03 資料夾搬移/改名後資料仍在；P-04 唯讀位置的退路與提示；P-05 兩個執行個體被擋（含殘留鎖偵測）；P-06 升級遷移＋備份＋拒絕較新 schema；P-07 備份還原往返資料一致；P-08 防毒/SmartScreen 行為已記錄。
